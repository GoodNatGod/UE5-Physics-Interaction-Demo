# UE5 Open-Area Physics Interaction Demo

![实机运行截图：火球触发多箱 Chaos 破裂](./Docs/Media/physics-interaction-demo.png)

这是一个面向**大世界交互策划 / 物理交互方向**的 UE5 可玩垂直切片。我把角色战斗视为玩家与环境沟通的输入方式，重点设计的是：环境如何理解玩家行为、给出有重量的反馈，并在开放区域中保持稳定、可调和可扩展。

| 项目项 | 当前定位 |
|---|---|
| 引擎 | Unreal Engine 5.8 |
| 作品集方向 | 大世界交互策划 / 物理交互原型 |
| 当前阶段 | 可分流战斗输入、木箱破坏、范围爆炸、表面反馈、动态吊桥 |
| 我的职责 | 交互规则、体验分层、参数设计、UE 原型实现与验收 |

> 这是面向“大世界交互设计”的局部可玩样本，不以当前测试场地宣称完成了大世界。角色与动作只承担交互输入和体验验证，不是本项目的最终主题。

## 玩家现在能体验到什么

| 玩家行为 | 环境反馈 | 我希望玩家读到的信息 |
|---|---|---|
| 近战攻击木箱 | 第一刀命中后立即破裂，碎片继承方向与重量 | 刀真的接触了物体，不是播放一段预设特效 |
| 开启武器碰撞可视化 | 直接看到刀身 Sweep 的时间与空间范围 | 命中结果可解释，方便策划调攻击手感 |
| 发射火球 | 范围内多个木箱同时响应，并触发火焰、碎片和贴花 | 同一种输入可以产生范围更大、层级更高的环境反馈 |
| 站上吊桥 | 桥面承受角色重量并产生轻微下沉 | 动态路径不是装饰，它在承载玩家 |
| 行走、跑步经过吊桥 | 跑步晃动明显强于行走 | 环境能反映角色当前运动强度 |
| 起跳与落地 | 起跳和落地把垂直动量分摊给脚下及相邻木板 | 垂直动作应比普通移动更明确，目前仍在调优 |
| 在桥上攻击 | 攻击推进和角色原生推力被隔离 | 攻击不应比落地更强烈地扰动动态路径，目前仍有异常峰值 |
| 移动后自由观察 | 镜头保持玩家选择的方向，不自动拉回角色背后 | 观察环境的控制权属于玩家 |

## 连招工程说明：把动作变成可选择的环境输入

连招不是这个作品集的最终主题，它是玩家向环境提交**方向、强度、持续时间和高度**的输入层。最初“一刀破箱”只能验证单次水平方向命中；本轮把输入扩展为四段轻击、上下文重击、飞剑和空中攻击，用同一套命中协议覆盖更丰富的环境测试场景。

| 玩家意图 | 当前输入路由 | 对环境交互的价值 |
|---|---|---|
| 连续点击 | `Attack01 -> 02 -> 03 -> 04 -> 01`，第四段窗口内可重新循环 | 连续测试多个目标，且不会在末段失去输入 |
| 边移动边接段 | 每次按下都重新采样当前移动方向，不继承上一刀朝向 | 玩家可以在箱群、机关和动态路径之间主动改选目标 |
| 短按 / 长按 | 短按进入轻击；通常长按进入 `Attack05` 重击 | 同一个按键表达轻量命中与高强度命中，不增加孤立操作 |
| 第三段长按 | `Attack03` 上下文优先进入“重击·鸣奏”，不会误触发普通重击 | 招式上下文可以改变交互强度，同时保持输入规则可预期 |
| 第三段飞剑 | 右手释放，飞到攻击方向前方固定点旋转，再回到左手 | 提供离身、持续、多阶段的空间 Sweep 样本 |
| 鸣奏后继续点击 | “重击·鸣奏”结束或窗口内回到 `Attack01` | 特殊攻击结束后重新进入基础交互循环 |
| 空中点击攻击 | `AirAttack_Start -> Loop -> End`，起手上升、峰值后俯冲、落地收尾 | 为地面材质、吊桥和未来水面提供清晰的垂直冲击向量 |

### 连段如何保持稳定

1. **动画窗口决定节奏**：每段 Montage 使用 `ComboWindow`；窗口前输入进入 `0.25s` 缓冲，窗口开启时立即消费，窗口内输入直接切到下一段。
2. **输入与方向一起缓存**：缓冲保存的不只是“按过攻击”，还保存当次选择的世界方向；切段前先转向，再创建攻击推进和武器 Trace，避免动作、位移与判定朝向分离。
3. **Tap / Hold 由上下文路由**：空闲起手等待松开或长按阈值；攻击中按下仍可先接轻击，持续按住后再按起始段上下文升级为普通重击或鸣奏。
4. **Notify 与状态使用 RequestId 握手**：每次切段递增请求 Id，`Started / Active / ComboWindow / ResonanceWindow / Recovery / Finished` 只处理当前请求，旧 Montage 的迟到 Notify 不会污染新攻击。
5. **Watchdog 按真实 Montage 时长兜底**：动画缺失、Notify 丢失或手调播放速度后，状态仍能释放；超时上限会覆盖当前 Montage 的实际播放时长，避免慢动作被误判为卡死。
6. **地面与空中循环隔离**：空中攻击使用独立攻击类型和 Section 状态，不推进、不继承地面 `ComboIndex`；落地后由 `End` 全身接管，再释放移动限制。

所有节奏、位移、Trace、飞剑轨迹和空中位移参数都集中在 `DA_RoverCombatConfig`。C++ 负责输入状态、生命周期和标准化命中，Montage / AnimNotify 负责动作时机；公开仓库不包含第三方动作资产，但保留了运行时规则、生成脚本和无头 PIE 验证脚本。

## 交互设计目标

### 1. 战斗输入也是环境语言

近战和火球不直接“认识木箱”。它们先表达命中位置、方向、强度、范围与表面，再由环境决定如何响应。这样同一套输入可以继续扩展到石块、金属装置、布料、草地和水面，而不需要为每个技能单独编写一套场景反应。

### 2. 重量感来自一组一致规则

我不把“飞得远”当作物理效果好。木箱、碎片和桥板都有明确质量；冲量、阻尼、重力和回收时间共同决定反馈。目标是让物体能被推动、破坏和晃动，同时避免纸片感、无限旋转和一碰就飞。

### 3. 动态环境首先要可靠通行

吊桥需要会动，但不能因为追求晃动而让玩家无法通过。桥面摆幅、横滚、端点约束和恢复速度都有边界：玩家能感到脚下变化，桥却不会穿透、散架或持续振荡。结构通过不等于体验通过，攻击、移动和落地必须使用可比较的实际桥体响应继续验收。

### 4. 大世界交互必须有生命周期预算

碎片、Niagara、贴花和临时对象都需要受控回收。当前原型已经把反馈生命周期纳入规则，后续扩展时会继续记录同时激活数量、回收时间、帧耗与内存，而不是只累加效果数量。

## 场景案例一：一刀破坏木箱

木箱承担最基础的“攻击环境”教学：玩家不需要学习新按键，只要沿用战斗输入，就能立即验证环境是否可交互。

- **玩家行为**：左键近战，刀身在有效帧内扫过箱体。
- **环境回应**：完整刚体切换为 Chaos 碎片，继承命中方向并产生表面粒子。
- **设计重点**：第一刀就破坏，减少重复试探；碰撞可视化帮助确认命中时机和范围。
- **重量控制**：当前箱体按约 `80kg` 量级调试，碎片使用更高阻尼，避免像泡沫一样飞散。
- **可调维度**：生命、质量、破裂冲量、扩散半径、碎片阻尼、保留时长和淡出时间。

## 场景案例二：火球触发群体反馈

火球用于验证同一交互规则能否从“单点命中”升级为“范围事件”。爆炸范围内的对象独立判断自身材质和响应方式，玩家可以从碎片方向、火焰反馈与贴花位置判断爆心影响。

- 近战强调方向准确和即时破坏；
- 火球强调范围、层级和同时响应；
- Wood 已完成真实装配，Stone / Metal 等表面仍处于后续差异化阶段；
- 爆炸效果不会永久留在场景中，避免开放区域持续累积临时对象。

## 场景案例三：60 板动态吊桥

我把吊桥定义为开放区域中的**动态路径节点**。玩家仅通过站立、步行、跑步、起跳和落地，就能从桥面的下沉、摆动和余振中读出自己的运动状态。

当前桥体由 `60` 块独立物理木板组成，使用 `4` 个可见桥墩 / 挂点和 `122` 个约束，桥面约 `16.77m x 4.00m`。每道板缝不再只使用一个中轴关节，而是在木板左右两侧各设置一条约束线。

| 体验问题 | 当前规则 |
|---|---|
| 桥够不够像一条可通行路径 | 木板 `400 x 25 x 6cm`，间隙 `3cm` |
| 是否有自然弧线 | 初始下垂 `80cm` |
| 是否有重量 | 单板 `15kg` |
| 跑步是否强于走路 | 输入冲量 `126.5 > 46.5` |
| 起跳和落地是否可读 | 输入冲量 `800 / 2200`，实际桥体层级仍在复核 |
| 中段是否容易侧翻扭曲 | 59 道板缝使用左右双侧挂点，以几何力臂抑制横滚 |
| 离开后是否会一直晃 | 10 秒后速度归零，自然姿态误差 `1.14°` |

宽木板使用单条中轴约束时，角色踩在一侧会形成较大的横向力臂，长链容易出现麻花状扭转。双侧结构中，主约束负责链长和前后俯仰，副约束释放垂直与角向自由度，只用第二个受力点稳定横滚，避免两套完整约束互相争抢。

结构方案已经通过无头 PIE，但交互手感仍有一个明确问题：Attack01 Recovery 阶段的桥体峰值约 `259.5cm/s`，高于落地后的 `119.7cm/s`。武器碰撞、世界交互请求、攻击推进、动画根运动和角色相对木板位移已经排除；下一轮将继续检查 Recovery 与动态 Movement Base 的帧级变化，并把攻击峰值加入自动失败门槛。

更完整的参数说明见 [物理吊桥系统说明](./Docs/物理吊桥系统说明.md)。

## 面向大世界的扩展顺序

1. **先完成表面语言**：让 Wood / Stone / Metal 在破坏方式、声音、粒子和残留痕迹上形成稳定差异。
2. **再扩展持续环境反馈**：全局风、Chaos Cloth、草地形变和水面交互共享世界参数。
3. **最后证明规模化**：使用 PCG、World Partition / HLOD 和固定测试路线记录 Actor 数量、加载距离、p50 / p95 帧时间与内存。

当前不会把未完成的系统写成能力清单。完整阶段规划见 [Roadmap](./Docs/Roadmap.zh-CN.md)。

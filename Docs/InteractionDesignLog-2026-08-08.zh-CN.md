# 交互设计日志 | 2026-08-08

## 今日目标

今天完成的不是“给角色多加几招”，而是把玩家与环境之间的输入语言从一次近战命中扩展为**可选方向、可选强度、可持续和可垂直作用**的完整样本。

物理交互 Demo 已经有木箱、范围爆炸和动态吊桥，但玩家输入仍存在三个限制：

1. 连击一旦开始就容易被上一段朝向锁住，无法在多个环境目标之间重新选择；
2. 同一个近战键只能表达一种强度，难以验证环境反馈的层级；
3. 地面攻击只能提供水平冲量，无法为桥面、地表和水面提供稳定的垂直作用样本。

本轮围绕这三个体验问题完成四段轻击、Tap / Hold、重击·鸣奏、飞剑和空中攻击。角色战斗仍是交互载体，不把项目重新定位为完整角色玩法复刻。

## 输入语言矩阵

| 输入维度 | 玩家行为 | 系统表达 | 可验证的环境问题 |
|---|---|---|---|
| 方向 | 连击中改变 `WASD` | 每段重新采样世界攻击方向 | 能否在箱群或机关之间快速改选目标 |
| 强度 | 短按 / 长按 | 轻击 / Attack05 重击 | 同一表面能否根据冲量层级给出差异反馈 |
| 上下文 | Attack03 长按 | 重击·鸣奏 | 招式阶段能否改变命中类型而不增加按键 |
| 持续空间 | Attack03 飞剑 | 飞出、定点旋转、回收三阶段 Sweep | 离身判定能否持续命中且不重复结算 |
| 垂直方向 | 空中按攻击 | 起手上升、峰值、俯冲、落地收尾 | 动态桥面和地表能否读到垂直冲击 |
| 连续性 | Attack04 / 鸣奏后继续点击 | 回到 Attack01 | 特殊段结束后是否存在输入死路 |

## 连招规则

### 四段轻击与逐段方向选择

地面轻击循环为：

```text
Attack01 -> Attack02 -> Attack03 -> Attack04
    ^                                  |
    +----------------------------------+
```

Attack04 的 `ComboWindow` 内继续输入会立即回到 Attack01；没有输入时，Attack04 自然完成并全身过渡到按脚位选择的站姿。

每次轻击按下都会从移动组件读取当前相机相对世界方向。输入在窗口前到达时，方向与按键一起进入缓冲；窗口开启后，角色先转向，再创建攻击推进和武器 Trace。这样动作表现、胶囊位移、刀身判定始终指向同一个目标。

没有方向输入时保持当前朝向，避免松开摇杆后无意转身。

### Tap / Hold 与上下文重击

鼠标左键同时承担轻击与重击，但路由规则由当前状态决定：

| 当前状态 | 短按 | 持续长按 |
|---|---|---|
| 空闲 | Attack01 | Attack05 |
| Attack01 / 02 / 04 | 继续轻击 | 达到阈值后升级为 Attack05 |
| Attack03 | 继续 Attack04 | 优先进入重击·鸣奏 |
| 重击 Recovery | 无轻击续段 | 可进入重击·鸣奏 |
| 重击·鸣奏 | 缓冲或窗口内回 Attack01 | 不继续扩展新的攻击类型 |

攻击中按下仍先响应轻击窗口，不让连招显得迟钝；如果同一次输入继续按住并达到阈值，再依据按下时的攻击上下文升级。Attack03 会记录独立来源标记，因此即使按下瞬间先进入 Attack04，持续长按也只会进入鸣奏，不会误触发 Attack05。

### Attack03 飞剑

最终轨迹语义为：

```text
右手释放 -> 攻击方向前方固定点 -> 定点旋转 -> 追踪左手回收
```

飞剑包含 `Waiting / Outbound / Spinning / Returning` 四个运行阶段。飞出、旋转和返回可分别开关碰撞，并使用独立 Sphere Sweep 半径、采样点数和时空子步进。单次 Attack03 内对命中对象去重，避免旋转阶段每帧重复伤害。

武器网格本身保持 `NoCollision` 且不模拟物理。环境只接收标准化命中请求，因此飞剑不会通过刚体组件碰撞直接给吊桥注入不可控能量。取消、受击、死亡、Montage 中断和 Watchdog 都会回收武器，避免残留在世界中。

### 重击·鸣奏与循环出口

Attack03 后半窗口和 Recovery 可以进入重击·鸣奏，普通重击 Recovery 也提供同一出口。鸣奏使用独立攻击类型、RequestId、位移和攻击定义，不伪装成轻击数组中的第五段。

鸣奏的 Startup / Active 输入先缓冲，ComboWindow 消费；Recovery 输入立即切回 Attack01。特殊招式因此不会成为操作死路，后续环境测试也能连续进行。

## 空中攻击：建立垂直交互向量

空中攻击使用一个 Montage 的三个 Section：

```text
AirAttack_Start -> AirAttack_Loop -> AirAttack_End
                         ^   |
                         +---+
```

- 空中按攻击直接进入 `AirAttack`，不经过地面 Tap / Hold；
- Start 的 `RoverAttackStarted` 确认后，根据目标上升高度、峰值时间和世界重力反算初速度；
- 源动画第 `10` 帧触发 `RoverAirAttackApex`，从上升切换为可调俯冲速度；
- 未落地时 Loop 自循环，落地后立即跳到 End；
- End 全身接管落地表现，再释放移动限制；
- 空中攻击不推进、不继承地面 ComboIndex。

这条输入可以继续用于验证木板落点扩散、地表材质差异、浅水水花半径和可破坏对象的顶部命中，而不是只服务角色动作观赏。

## 工程稳定性规则

### 动画窗口与输入缓冲

- `ComboWindow` 决定下一段可立即切换的时间；
- `ResonanceWindow` 为 Attack03 提供独立上下文分流；
- 窗口前输入进入 `AttackInputBufferDuration`，当前完整工程验证的缓冲过期约 `0.261s`；
- Montage 完全结束后由 `ComboResetDuration` 保留短续接期，当前手调资产验证约 `0.392s`；
- 节奏参数来自 DataAsset，自动化测试读取资产当前值，不把旧三连节奏写死在脚本里。

### RequestId 握手

每个新攻击段都会生成新的 RequestId。AnimInstance 镜像当前请求，Montage 中的 `Started / Active / ComboWindow / ResonanceWindow / Recovery / Finished` Notify 回调时必须携带匹配的 Id。

这解决了快速切段时的典型问题：旧 Montage Blend Out 期间迟到的 Finished 或窗口关闭事件，不能结束新攻击、关闭新 Trace 或清空新输入。

### Watchdog

动画缺失、Notify 丢失、Montage 被意外中断时，Watchdog 会统一释放攻击状态、移动限制和飞剑生命周期。攻击 Active 超时不是固定假定动作时长，而是覆盖当前 Montage 按 PlayRate 计算后的真实时长，避免策划调慢动作后被系统提前取消。

# 交互设计日志 | 2026-08-07

## 今日目标

今天的目标不是再增加一个“物理功能”，而是把吊桥从小型组件测试改造成可以放进开放区域路线中的动态路径，并解决两个直接影响玩家体验的问题：

1. 桥要能通过外形、下垂和受力让玩家一眼认出它；
2. 角色移动后，镜头不应自动抢回观察方向。

## 吊桥体验规则

我希望玩家无需看 UI，仅凭脚下反馈就能区分当前行为：

```text
站立 < 行走 < 跑步 < 起跳 < 落地
```

- **站立**只产生持续重量，不重复触发脚步冲量；
- **行走 / 跑步**根据水平速度产生周期冲量，跑步必须明显强于行走；
- **起跳**在角色离开桥板时，把一部分离板动量传回最后接触的木板；
- **落地**读取落地前的垂直速度，形成整套行为中最强的单次冲击；
- **离开桥面**后，余振应自然衰减并回到稳定状态。

当前实测结果：

| 行为 | 实测冲量 |
|---|---:|
| 行走 | `23.3` |
| 跑步 | `63.2` |
| 起跳 | `241.1` |
| 落地 | `366.1` |

结果符合预期层级，没有把攻击动作误识别成脚步冲量。

## 从“小桥”到开放区域路径

最初的 12 至 15 板原型更像物理组件样例，不足以承担路线节点。今天做了三次尺度升级：

1. 取消木板数量的硬上限，只保留 `>= 12` 的安全下限；
2. 将实例扩展到 `60` 块木板，加入 `120cm` 的自然预下垂；
3. 将桥宽扩展到 `2m`，每端从一个中心挂点升级为左右两个挂点。

当前尺度：

| 项目 | 当前值 |
|---|---:|
| 木板数量 | `60` |
| 木板尺寸 | `200 x 25 x 6cm` |
| 木板间隙 | `3cm` |
| 可见桥面 | 约 `16.77m x 2.00m` |
| 初始下垂 | `120cm` |
| 桥墩数量 | `4` |
| 挂点数量 | `4` |
| 约束数量 | `63` |
| 单板质量 | `15kg` |

## 四挂点的设计取舍

宽桥如果仍然只有中间一个挂点，视觉上不像两侧被绳索或铁链支撑；但如果每端使用两组完全相同的强约束，端板会被重复锁定，容易抖动或互相拉扯。

当前把两侧挂点分为互补职责：

- **主挂点**承受完整位置约束，并允许有限的前后摆动；
- **副挂点**负责横向稳定，释放垂直和角度自由度；
- **板间约束**保留前后摆，严格压低侧向摆和扭转。

这套规则让四个挂点在视觉上成立，同时不会把宽桥变成刚性平台或过约束结构。

## 调参逻辑

参数按体验问题分组，而不是按组件分组：

| 体验问题 | 主要调节项 | 当前值 |
|---|---|---:|
| 桥有多长、多宽、弧线多深 | 木板数、尺寸、间隙、下垂 | `60` 板、`2m` 宽、`120cm` 下垂 |
| 桥有没有重量 | 单板质量 | `15kg` |
| 行走和跑步差异是否清楚 | 参考速度、脚步冲量、间隔 | `600cm/s`、`90`、`0.20s` |
| 起跳是否会压回桥面 | 起跳阈值、比例、上限 | `120cm/s`、`0.004`、`250` |
| 落地是否足够有冲击 | 落地阈值、比例、上限 | 比例 `0.006`、上限 `500` |
| 中段是否扭曲 | 前后摆、侧摆、扭转 | `10° / 2° / 0°` |
| 离开后是否能恢复 | 线性 / 角阻尼 | `1.5 / 4.0` |

## 稳定性验收

吊桥的验收标准不是“它会动”，而是“它在会动的同时仍能作为路径使用”。

| 验收项 | 结果 |
|---|---:|
| 角色加载后的中心附加下沉 | `15.2cm` |
| 6 秒恢复后的线速度 | `0.0cm/s` |
| 6 秒恢复后的角速度 | `0.0deg/s` |
| 端点最大误差 | `0.56cm` |
| 板间最大误差 | `0.45cm` |
| 构造态挂点 Frame 误差 | `0.000cm` |

相邻木板关闭互撞，并启用 CCD、Mass Conditioning 与更高 Solver 迭代，避免木板穿透、弹飞和长链约束累计误差。专项无头 PIE 已覆盖四挂点、质量一致、行为冲量层级、恢复和误差上限。

## 镜头控制权

原逻辑会在玩家停止观察或移动一段时间后，把镜头自动转向角色或最后移动方向。这对于需要观察物理场景的 Demo 会打断玩家判断，因此今天将自动跟随插值速度设为 `0`，保留自由观察。

专项验证场景中，角色朝向与镜头相差 `90°`，等待超过原本的 `0.3s` 回正延迟后，镜头最大 Yaw 漂移为 `0.00°`。基础角色 PIE 同时通过。

# 攻击空间扰动特效实现方案 — 鸣潮风格拆解 + UE5.8 落地规格

> **用途**：为漂泊者攻击系统补充"空间扰动"表现层。本文档先拆解鸣潮（Wuthering Waves）在虚幻引擎中的特效组织方式与空间扰动的视觉语言，再给出本项目 UE 5.8 下可执行的资产 + C++ 实现规格。
> **交付目标**：Codex 实现文档（按 §9 优先级逐阶段交付，每阶段通过 §8 验证后进入下一阶段）
> **前置条件**：四段普攻 + 重击 + 鸣奏 + 飞剑 + 武器 Trace 已通过 PIE 验证（见 `漂泊者衍射攻击系统扩展规格.md` §10）
> **版本**：1.0.0 · 2026-08-08
> **事实标注约定**：`[已知]` = 鸣潮官方分享/公开资料可证；`[推断]` = 基于游戏内观察与行业通用做法的合理推测，Codex 实现时无需求证，但不得写入交付口径。

## 0. 文档用途与交付边界

### 0.1 要解决什么问题

当前攻击系统的命中链路（Trace → 伤害 → 受击动画）已闭环，但攻击的**表现层只有武器显隐**，没有刃光、没有命中反馈、没有"衍射/空间撕裂"的视觉语言。本文档定义：

1. 鸣潮这类二次元 ACT 的攻击特效是怎么组织的（驱动层/表现层/反馈层）；
2. "空间扰动"具体是哪些可复现的技术（折射材质、后处理扭曲、Niagara 粒子、顶点扰动）；
3. 本项目按什么架构落地（C++ 只做协议与生命周期，Niagara/材质只消费数据，参数全进 DataAsset）。

### 0.2 不做的事（范围外）

- **不**做全屏大范围"时间停止/空间坍缩"级特效（那是共鸣解放/大招的范畴，P2 后再说）。
- **不**改战斗判定链路——特效是纯表现，任何特效改动不得触碰 `URoverCombatComponent` 的 Trace/伤害/连招逻辑。
- **不**在 Tick 里跑特效逻辑；Niagara 由自身模拟驱动，C++ 组件零每帧开销。
- **不**硬编码任何数值；所有参数进 `URoverVFXConfig`（DataAsset）。

## 1. 鸣潮特效体系技术拆解

### 1.1 技术底座 `[已知]`

- 鸣潮基于 **UE4 魔改版**（Unreal Fest 上海 2023 官方分享《基于虚幻引擎4的多平台效果和性能优化实践》，重点在延迟渲染、TAAU 管线改造、OnePass Deferred Shading、多平台树方案、Chaos 破碎 + Niagara）。
- 战斗特效（含声骸技能、必杀技）由**一套统一的材质控制器 + Niagara 特效系统管理，配置在战斗循环中** `[已知]`（官方采访原文："我们用一套统一的材质控制器和 Niagara 特效系统来进行管理，它被配置在战斗循环中"）。
- 声骸相关表现（击溃/掉落/吸收/唤醒）在色彩上统一偏向金色，溶解/吸收用曲线感强的纹理 `[已知]`。
- 团队自己开发了风格化昼夜系统，天空非体积云方案——说明其渲染栈有大量自研改造，**特效管线则走 UE 标准 Niagara + 材质** `[已知]`。

**对本项目的结论**：鸣潮的特效不是"每个技能一个孤立的粒子资产"，而是**统一材质控制器（共享材质参数体系）+ Niagara（表现载体）+ 战斗循环事件（驱动时机）**三层结构。本项目照此组织。

### 1.2 战斗特效的分层结构 `[推断，行业通用]`

| 层 | 职责 | 鸣潮里的表现 | 本项目对应 |
|----|------|-------------|-----------|
| **驱动层** | 何时触发、持续多久、挂在哪个骨骼 | AnimNotify / 技能蓝图事件 | 现有 `RoverAttackActiveBegin/End`、`ResonanceWindow` AnimNotify |
| **表现层** | 粒子、网格、光效、拖尾 | Niagara 系统（刃光、能量带、涟漪） | `NS_Rover_*` 系列（本文档 §6） |
| **反馈层** | 命中瞬间、受击、环境反应 | 命中闪光、受击粒子、声骸吸收 | 命中涟漪（本文档）+ 已有物理交互反馈（`NS_P0_Explosion` 等） |
| **后期层** | 全屏/局部视觉统一（扭曲、色差、时缓） | 爆发技、共鸣解放的屏幕扭曲 | `PP_Rover_AttackDistortion`（P2） |

### 1.3 鸣潮"空间扰动"的视觉语言 `[推断，基于游戏内观察]`

鸣潮的"空间扰动"不是一个特效，而是一族同源的视觉手段，常见于：

1. **刃光折射**：挥砍时剑刃拖出的光带本身半透明，且让背景产生轻微扭曲（光带材质带 Refraction）。
2. **命中空间涟漪**：命中点出现一圈圈向外扩散的环状扭曲（类似水面涟漪但发生在空气中），背景被径向拉伸。
3. **突进空气扭曲**：突进/闪现路径上的空气扭曲柱（鸣奏、闪避反击时尤其明显），常配合残影。
4. **能量球/飞剑扭曲**：飞行物核心是折射球体，边缘有扰动壳（Attack03 飞剑、技能弹道）。
5. **吸收/坍缩扭曲**：声骸吸收、能量汇聚时，目标点周围空间向中心塌陷（径向 UV 收缩）。
6. **全屏色差 + 径向扭曲**：共鸣解放/时缓瞬间，屏幕边缘径向扭曲 + 色差，几百毫秒内恢复。

**风格化共性**：扭曲强度**小**（折射偏移 ≤ 0.1，全屏扭曲 ≤ 0.02 UV），**时间短**（单次 0.15~0.4s），**与光效叠加**而非独立存在——扭曲是"画龙点睛"，主角永远是光。

## 2. 空间扰动的核心技术路线（UE 实现原理）

### 2.1 路线 A：材质折射（Refraction pin）—— 局部扰动主力

**原理**：`Blend Mode = Translucent` 的材质暴露 `Refraction` 输入，偏移其下方场景的采样。法线贴图 + Panner 产生流动扭曲。UE 官方文档明确此方法适用于"热浪、剧烈爆炸造成的空气扭曲、能量特效"。

**关键参数**：`Refraction` 值 ≈ 0.01~0.1（不是物理 IOR，是场景偏移量）；`Refraction Depth Bias` 防止近处物体锐角穿帮；法线贴图两个反向 Panner 叠加产生有机流动。

**成本**：按覆盖像素计。局部小片（刃光/命中环）极便宜；全屏面片贵。

**本项目用法**：所有局部扰动的基底。刃光片、命中涟漪、飞剑壳全部用它。

### 2.2 路线 B：后处理材质全屏/局部扭曲 —— 爆发时刻

**原理**：`Material Domain = Post Process`，采样 `SceneTexture: PostProcessInput0`，对其 UV 施加噪声偏移后重新输出。结合**深度 mask**（`SceneTexture: SceneDepth`）或 **Custom Stencil** 限制扭曲范围，避免全屏晃动。

**关键参数**：UV 偏移幅度 ≤ 0.02（全屏）~ 0.05（局部）；Noise 贴图 tiling 4~8；扭曲强度曲线 0→峰→0（0.3s 内）。

**成本**：全屏一次采样 + 少量指令，GPU 上约 0.1~0.3ms（1080p，视 mask 复杂度）。只能有一个 PP 材质槽时需与项目现有 PP 协商（本项目当前无 PP 占用，可直接挂）。

**本项目用法**：P2 阶段给鸣奏/重击/终结段加"爆发瞬间 0.2s 径向扭曲 + 色差"。

### 2.3 路线 C：Niagara 粒子系统 —— 载体与动态

**原理**：粒子负责"形状、运动、生命周期"，材质负责"外观"。空间扰动类特效在 Niagara 中的标准做法：

- **Ribbon 渲染器**：刃光拖尾（多粒子连线成带，给 ribbon 的 mesh 材质加 Refraction）。
- **Sprite/Quad 渲染器**：命中涟漪（一个始终面向相机的圆片，材质内做径向 UV 扭曲环）。
- **Mesh 渲染器**：飞剑周围的扭曲壳（复制一份半透明放大网格，材质折射）。

**关键技巧**：
- 扰动粒子的 Spawn 时机由事件驱动（`Spawn Burst Instantaneous` + 外部事件触发），不是持续发射；
- 拖尾位置用 Ribbon + 粒子年龄控制头尾宽度/透明度渐变（头部亮、尾部透明）；
- 扰动强度用 `Particle Age` 归一化曲线驱动（0→峰→0），粒子死亡自动衰减，无需 C++ 干预。

**成本**：粒子数可控（刃光 ≤ 64 粒子、涟漪 1 片、拖尾 32 段），移动端友好。

### 2.4 路线 D：网格顶点扰动（WPO）/残影

**原理**：半透明网格材质用 `World Position Offset` 加噪声让网格表面波动（如传送门漩涡感）；残影 = 上一帧角色 pose 的半透明复制淡出（Niagara Mesh Renderer 或 Mesh Deformer）。

**成本**：残影复制 mesh 成本高，慎用。

**本项目用法**：P2 可选。鸣奏突进残影用 Niagara `Mesh Renderer` + 淡出材质，单段攻击最多 3~5 个残影实例。

### 2.5 路线对比表

| 路线 | 效果 | GPU 成本 | 制作难度 | 适用场景 | 本项目阶段 |
|------|------|---------|---------|---------|-----------|
| A 材质折射 | 局部空气扭曲 | 低~中（按像素） | 低 | 刃光、命中环、飞剑壳 | **P0** |
| B 后处理扭曲 | 全屏爆发感 | 中（0.1~0.3ms） | 低 | 爆发/终结/时缓 | P2 |
| C Niagara 粒子 | 动态形状与运动 | 低（可控） | 中 | 拖尾、涟漪载体 | **P0** |
| D WPO/残影 | 空间撕裂/残留 | 中~高 | 中~高 | 突进残影、漩涡 | P2 |

> **组合策略（鸣潮同款）**：A + C 是常态组合（Niagara 出形状，材质出扭曲），B 只用在爆发时刻，D 按需点缀。

## 3. 本项目设计定位：攻击 → 空间扰动映射表

漂泊者是**衍射（Spectro，光）属性** `[推断]`，风格基调：青白/冷白光 + 金色点缀 + 空间涟漪。各攻击动作的扰动设计：

| 攻击 | 扰动表现 | 技术组合 | 触发挂点（现有 Notify） | 时长 |
|------|---------|---------|----------------------|------|
| Attack01~02（横斩/回斩） | 刃光带 + 微折射 | A + C（Ribbon） | `RoverAttackActiveBegin` → `ActiveEnd` | 0.3s |
| Attack03（飞剑） | 飞剑轨迹扭曲 + 剑体折射壳 | A + C（Ribbon + Mesh） | 现有飞剑系统事件 + `ActiveBegin` | 全阶段 |
| Attack04（回旋） | 大范围刃光环 | A + C（Ribbon 环形） | `ActiveBegin` → `ActiveEnd` | 0.35s |
| Attack05（重击·后退） | 后退路径空气扭曲 + 命中大涟漪 | A + B（弱） | `ActiveBegin` | 0.4s |
| 鸣奏 EX01（突进） | 突进空气扭曲柱 + 残影（P2） | A + C（拖尾）+ D | `ActiveBegin` | 0.5s |
| **命中瞬间（所有攻击）** | 命中点空间涟漪 + 冲击环 | A（Quad 折射片） | `ProcessTraceSegment` 命中事件（新转发） | 0.25s |
| 完美闪避/爆发（P2） | 全屏径向扭曲 + 色差 0.2s | B | 时缓事件 | 0.2s |

**设计铁律**（鸣潮风格共性，写入验收标准）：
1. 扭曲强度克制：`Refraction ≤ 0.1`，后处理 UV 偏移 ≤ 0.02；
2. 光效为主、扭曲为辅：没有光的扭曲是"脏"，没有扭曲的光是"贴纸"；
3. 每个特效 ≤ 0.5s，攻击结束 0.1s 内全部消失（不留尾巴）；
4. 不遮挡战斗可读性：刃光透明度 ≥ 0.3，命中涟漪不盖住受击动画。

## 4. 架构方案（符合 AGENTS.md 约束）

### 4.1 C++ / 资产边界

```
┌─ C++（协议、状态、生命周期，零 Tick 开销）──────────────┐
│  URoverVFXComponent（新增，挂 ARoverCharacter）          │
│    ├─ 消费 Character 转发的事件（攻击开始/结束/命中/鸣奏） │
│    ├─ 从 URoverVFXConfig（DataAsset）查"当前攻击的特效描述"│
│    ├─ Spawn/Deactivate Niagara 实例（绑定到骨骼 Socket）  │
│    ├─ 命中点特效的短暂对象管理（池化/超时回收）            │
│    └─ 不持有任何游戏逻辑、不反向引用战斗组件              │
└──────────────────────────────────────────────────────┘
                          │ 只消费数据
                          ▼
┌─ 资产层（表现与调参，设计师领地）────────────────────────┐
│  Content/Rover/VFX/                                      │
│    ├─ Niagara/  NS_Rover_SwordTrail / HitDistortion /    │
│    │            DashDistortion                            │
│    ├─ Materials/ M_Rover_DistortionCore（折射基底）等     │
│    └─ Config/ DA_RoverVFXConfig（所有参数）               │
└──────────────────────────────────────────────────────────┘
```

**为什么不把特效逻辑塞进 `URoverCombatComponent`**：AGENTS.md 明确"角色/战斗只负责产生标准化交互请求，由子系统分发"。特效是表现，战斗组件加了特效逻辑会破坏"判定与表现解耦"；命中事件经 Character 转发到 VFXComponent，战斗组件只多一个委托广播（§7.2），改动最小。

### 4.2 挂点与生命周期

- **攻击期刃光**：复用现有 `RoverAttackActiveBegin/End` AnimNotify（所有 Montage 已有）→ Character 转发 → VFXComponent 按 `CurrentAttackType + ComboIndex` 查配置播对应特效，绑定到 `WeaponTraceBase/WeaponTraceTip` 之间的 ribbon 或 `RoverWeapon` socket。
- **命中涟漪**：`URoverCombatComponent::ProcessTraceSegment()` 命中处新增广播 `OnAttackHitConfirmed`（带命中点、法线、攻击类型）→ Character 转发 → VFXComponent 在命中点 Spawn `NS_Rover_HitDistortion`。
- **鸣奏突进扭曲**：`ResonanceWindow` 或 `ActiveBegin` 事件，绑定到角色根骨骼（拖尾从角色位置发出）。
- **回收**：Niagara 系统自身 `System Lifecycle` 自动结束；C++ 侧只对"命中点特效"做 5s 超时兜底回收（防止关卡卸载泄漏）。
- **角色销毁/死亡**：`EndPlay` 时 Deactivate 全部实例。

## 5. 资产实现规格（节点级步骤，Codex 照做）

> 制作顺序：5.0 公共材质 → 5.1 刃光 → 5.2 命中涟漪 → 5.3 突进扭曲 → 5.4 后处理（P2）。
> 所有材质 Blend Mode = **Translucent**、Lighting Mode = **Unlit**（扭曲不需要光照），`Two Sided = true`。

### 5.0 公共基底材质 `M_Rover_DistortionCore`

**用途**：被其他扰动材质作为**材质函数/基础模板**复用，统一"法线流动 → Refraction"逻辑，实现鸣潮"统一材质控制器"的组织方式。

**材质属性**：
```
Blend Mode    = Translucent
Shading Model = Unlit
Two Sided     = true
Refraction Depth Bias = 8.0   // 防近处锐角穿帮
```

**节点网络**（材质函数 `MF_Rover_DistortionFlow`，参数暴露）：
```
[TextureSample T_Rover_Noise_N] ──(UV: Panner A: Speed(0.05, 0.08))──┐
[TextureSample T_Rover_Noise_N] ──(UV: Panner B: Speed(-0.04, 0.06))─┴→ Lerp(0.5) → Normal
Normal × DistortionStrength(参数, 默认 0.8) → Refraction 输入
```

**参数清单**：`DistortionStrength`（0~1，默认 0.6）、`FlowSpeedA/B`（Vector2）、`Tiling`（默认 3）。

### 5.1 刃光 `NS_Rover_SwordTrail` + `M_Rover_TrailRibbon`

**视觉目标**：武器挥砍时拖出青白色光带，光带边缘让背景轻微扭曲（折射 0.04~0.08），头亮尾淡，0.3s 消失。参考：鸣潮普攻刃光 `[推断]`——冷白渐变 + 细长。

**Niagara 结构**（单发射器，Ribbon Renderer）：

| 模块 | 设置 |
|------|------|
| Emitter 更新 | `Spawn Burst Instantaneous`（1 次，由外部事件触发，非持续） |
| Particle Spawn | `Initialize Particle`：Position = 武器 Tip socket 世界位置；Color = 青白 (0.75, 0.95, 1.0)，Alpha 起点 0.9 |
| Particle Update | `Update Age`；`Scale Color`（Age 0→0.15s：Alpha 0.9→0.3；0.15→0.3s：→0）；`Solve Forces and Velocity` 关闭（跟随武器） |
| Ribbon Renderer | `Ribbon Width` = 4~8cm（头宽尾窄，用 Age 曲线）；`Facing Mode` = Screen；Mesh Source = 自定义平面网格或 ribbon 默认 |
| 事件驱动 | Niagara `On Event` 绑定 C++ 传入的 `TrailSpawn` 事件（每帧从 C++ 侧用 `Set Niagara Variable` 注入 Tip socket 位置——见 §7.1 `UpdateTrailPosition`） |

> **实现要点**：Ribbon 需要持续喂位置。两种做法二选一：
> - **推荐**：Niagara 组件 `SetNiagaraVariableVec3`（每帧在 VFXComponent 的 Tick 里仅对"正在播放刃光的实例"更新——**每帧开销仅 1 次向量拷贝，不是逻辑计算**，满足"Tick 无重活"约束；也可用 Niagara 的 `Position from Socket` 事件源替代，若 5.8 可用则 C++ 零 Tick）。
> - 备选：Ribbon 粒子生成在 Tip socket 并设置 `Kill on Distance`，让武器自带拖尾（不依赖 C++）。

**材质 `M_Rover_TrailRibbon`**（基于 5.0 函数）：
```
基础色：渐变（头部 0.9 白 → 尾部 0.3 青白，由 Ribbon 粒子 Color 驱动）
+ Emissive：Color × 2（Unlit 下靠亮度）
+ Refraction：MF_Rover_DistortionFlow（强度 0.5~0.8）
Blend = Additive 与 Translucent 之间权衡：
  用 Translucent（保留折射）+ 材质内 Additive 混合 → 推荐
```

**性能预算**：≤ 64 Ribbon 粒子，1 Draw Call。

### 5.2 命中空间涟漪 `NS_Rover_HitDistortion` + `M_Rover_RippleQuad`

**视觉目标**：命中点出现 1~2 圈环形扭曲（0.25s 内扩散 + 衰减），径向拉伸背景，青白色描边。这是鸣潮攻击最有辨识度的"空间扰动"时刻 `[推断]`。

**Niagara 结构**（单发射器，Sprite/Quad Renderer）：

| 模块 | 设置 |
|------|------|
| Emitter 更新 | `Spawn Burst Instantaneous`（1 粒子，外部事件触发） |
| Particle Spawn | Position = 命中点 + 法线偏移 2cm；`Mesh Orientation` = 面向相机（Billboard） |
| Particle Update | `Scale Sprite Size`：0→0.25s 由 10cm 线性扩到 90cm（曲线缓出）；`Scale Color`：Alpha 0.8→0 |
| 渲染 | Sprite，材质 = M_Rover_RippleQuad，`Sort Priority` 高（盖在受击动画上层但半透明） |

**材质 `M_Rover_RippleQuad`**（关键：径向扭曲环）：
```
UV = 以片中心为原点径向坐标（dist = length(UV - 0.5)）
环带 = 1 - smoothstep(0.3, 0.7, dist) × 波纹(sin(dist × 20 - Time × 8))
Refraction = 环带 × 径向方向(dir = normalize(UV-0.5)) × 0.08   // 径向拉伸！
Emissive = 环带 × 青白(0.7, 0.9, 1.0) × 0.8
```

> **实现要点**：扭曲方向必须是**径向向外**（`dir × 强度`），否则涟漪看起来像贴纸。这是"空间扰动"与普通光效的本质区别。

### 5.3 突进空气扭曲 `NS_Rover_DashDistortion` + `M_Rover_DashTube`（鸣奏专用）

**视觉目标**：鸣奏突进（0.25s、400cm）路径上留下柱状空气扭曲 + 细长光条，突进结束 0.2s 内消散。

**Niagara 结构**（Ribbon + 少量 Sprite 光尘）：

| 模块 | 设置 |
|------|------|
| Ribbon 发射器 | 同 5.1 的 Ribbon 位置注入方案；宽度 12cm；Color 金色偏白 (1.0, 0.9, 0.7)，Alpha 0.5 |
| Sprite 发射器 | 突进路径上 8 颗光尘，`Noise Force` 轻微抖动，Alpha 0.3 |
| 生命周期 | 系统时长 0.5s，1 次触发 |

**材质 `M_Rover_DashTube`**：柱状法线流动（法线贴图沿 Ribbon U 方向拉长，Tiling U=8 V=1）+ Refraction 0.06 + 柔和边缘（smoothstep 去边缘硬边）。

### 5.4 后处理扭曲 `PP_Rover_AttackDistortion`（P2）

**视觉目标**：鸣奏触发/重击命中瞬间，屏幕边缘 0.2s 径向扭曲 + 色差，恢复无痕。参考鸣潮共鸣技能爆发瞬间 `[推断]`。

**材质**（Material Domain = Post Process）：
```
SceneTexture: SceneDepth → 深度 mask（近处 ≤ 3m 不扭曲，避免角色自身变形）
Noise 采样（Tiling 8）→ 偏移向量 = Noise.xy × DistortionAmount(0.02) × Mask
UV' = UV + 偏移向量（径向分量加强：dir = UV - 0.5, 偏移 += dir × 0.01 × Mask）
输出 = SceneTexture: PostProcessInput0 用 UV' 采样
色差 = 额外采样两次 R/B（偏移 ±0.002），混合
强度包络：由 C++ 传入的时间参数驱动（0→1→0，0.2s）
```

**接入**：P2 时由 VFXComponent 在触发时创建一个仅影响本地的 PostProcessVolume（或改全局 PP 参数，用 `Scalability` 分组区分），结束后销毁。**不做常驻 PP**。

## 6. 触发事件与 C++ 集成点（改动最小化）

### 6.1 现有 Notify 复用（零 Montage 改动）

所有攻击 Montage 已带 `RoverAttackActiveBegin/End` Notify → `URoverAnimInstance` → `ARoverCharacter` 转发。新增转发目标：

```
ARoverCharacter::HandleAttackActiveBeginNotify(RequestId)   // 已有，追加一行：
    → VFXComponent->OnAttackActiveBegin(CombatComponent->GetCurrentAttackType(), CombatComponent->GetCurrentComboIndex());

ARoverCharacter::HandleAttackActiveEndNotify(RequestId)     // 已有，追加一行：
    → VFXComponent->OnAttackActiveEnd();
```

**零风险**：只追加调用，不改现有转发逻辑；VFXComponent 未配置时直接 return。

### 6.2 命中事件（战斗组件唯一改动）

`URoverCombatComponent` 新增**广播委托**（不改判定逻辑）：

```cpp
// RoverCombatComponent.h
DECLARE_DYNAMIC_MULTICAST_DELEGATE_ThreeParams(
    FRoverAttackHitBroadcast, const FVector&, HitLocation,
    const FVector&, HitNormal, ERoverAttackType, AttackType);

UPROPERTY(BlueprintAssignable, Category = "Rover|Combat|VFX")
FRoverAttackHitBroadcast OnAttackHitConfirmed;   // 仅广播，组件不关心谁听
```

在 `ProcessTraceSegment()` 命中分支末尾 `OnAttackHitConfirmed.Broadcast(Hit.ImpactPoint, Hit.ImpactNormal, CurrentAttackType);`。`ARoverCharacter::BeginPlay` 绑定：`CombatComponent->OnAttackHitConfirmed.AddDynamic(this, &ARoverCharacter::HandleAttackHitConfirmed)` → 转发给 VFXComponent。

### 6.3 生命周期兜底

- `VFXComponent->EndPlay`：Deactivate 所有持有的 NiagaraComponent，清空池。
- 命中特效超时：`HitEffectTimeout`（默认 5s）后用 Timer 回收（TimerHandle 存成员，EndPlay 清）。
- 角色死亡（`HandleDeath` 事件）→ 立即 Deactivate 刃光/拖尾（鸣潮被打断时特效同样收掉 `[推断]`）。

## 10. 风险与规避

| 风险 | 概率 | 影响 | 规避 |
|------|:----:|------|------|
| Ribbon 位置注入依赖 C++ 每帧 SetNiagaraVariable | 中 | 违反"零 Tick"审查 | 优先用 Niagara socket 跟随；C++ 注入方案只允许在既有帧函数中顺带执行（1 次向量拷贝），并注释说明 |
| 折射 Depth Bias 不足导致近景穿帮 | 中 | 视觉扣分 | 5.0 材质默认 `Refraction Depth Bias = 8`，8.2 近景检查 |
| 全屏后处理与项目未来 PP 冲突 | 低 | 画面异常 | P2 用局部 PPVolume，不占用全局 PP 槽 |
| 命中广播高频触发（多段 Trace 命中同一帧） | 中 | 特效泛滥 | `MaxSimultaneousHitEffects` 限流 + 同帧同攻击合并（组件内去抖 0.05s） |
| 特效资产引用软指针加载失败（首次进入 PIE 卡顿） | 低 | 短暂无特效 | 软指针 `LoadSynchronous` 在首次触发时加载并缓存；配置资产在角色 BeginPlay 预载 |
| 鸣奏突进速度过快（400cm/0.25s）导致拖尾断裂 | 中 | 拖尾不连续 | Ribbon 采样密度调高（粒子数 32→64），SubUV 沿路径拉伸 |

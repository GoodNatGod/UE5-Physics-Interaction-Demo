> **用途**：在现有三段普攻系统基础上扩展第4段普攻、重击、重击·鸣奏、重击·余音，以及尘微之声能量系统

> **前置条件**：三段普攻（Attack01~03）已完整实现，包含飞剑系统、武器Trace、请求-确认-Watchdog机制  
> **版本**：1.1.0  
> **日期**：2026-08-08  
> **当前实施状态**：P0-1 至 P0-5 与跳跃攻击均已完成并通过自动化验证：第4段普攻、攻击类型/统一入口、Tap/Hold、Attack05 重击、重击·鸣奏及 `AirAttack_Start -> Loop -> End` 已接入运行时。当前最终规则为 Attack03 起始长按进入鸣奏、其他轻击起始长按进入 Attack05、鸣奏后攻击接回 Attack01；P0-6 余音触发方式需基于现有循环重新设计。

## 0. Fun Hypothesis & Design Pillars（本扩展）

### Fun Hypothesis

> **玩家在第三段普攻后有意识地选择"继续连段"或"稍停触发鸣奏"——这个时机决策本身就是好玩的核心，而不是按键速度。**

### Design Pillars

| # | Pillar | 含义 | 检验标准 |
|---|--------|------|---------|
| 1 | **不破坏现有手感** | 第1-3段普攻的响应速度、连招窗口、取消规则零回归 | 现有三段连招 PIE 回归测试全通过 |
| 2 | **输入意图可读** | 玩家短按=普攻/连携、长按=重击，系统在 0.12s 内做出正确判定 | 100次混合输入零误判 |
| 3 | **连携是奖励不是惩罚** | 鸣奏/余音的触发窗口要宽容到"有意稍停就能触发"，不是帧精确 | 非速通玩家 5 分钟内成功触发鸣奏 ≥ 3 次 |
| 4 | **能量有反馈** | 尘微之声的获取和消耗有清晰的视觉/数值反馈 | 玩家能说出"余音打中加了能量" |

## 1. 鸣潮原版机制拆解

### 1.1 攻击体系总览

| 攻击类型 | 触发方式 | 能量交互 | 核心特征 | 对应FBX（推测） |
|---------|---------|---------|---------|----------------|
| 普攻 1-3段 | 短按攻击键 | 无 | 已实现，Attack03含飞剑 | AM_Attack01~03 ✅已用 |
| **普攻 4段** | 第3段后短按（ComboWindow内） | 无 | 连招循环边界；窗口内再按回普攻1，无输入则回Idle | AM_Attack04 |
| **重击** | 长按攻击键 | 消耗耐力 | 后退位移 + 飞剑连续命中 | AM_Attack05 |
| **重击·鸣奏** | 第3段普攻/重击后，稍延迟短按 | 无 | 突进攻击，高追尾性能 | AM_Attack_EX01 |
| **重击·余音** | 鸣奏后/闪避反击后短按 | 获取尘微之声~40Pt | 连携终结，主要能量来源 | AM_Attack_EX02 |

### 1.2 关键机制说明

**重击·鸣奏的时机判定（核心难点）**：
- 第3段普攻的 ComboWindow 内**最速输入** → 触发第4段普攻
- 第3段普攻的 ComboWindow 内**稍延迟输入**（ComboWindow 后半段） → 触发鸣奏
- 第3段普攻 Recovery 期间输入 → 触发鸣奏
- 第3段普攻 Recovery 结束后（ComboResetDuration 内）输入 → 触发鸣奏

> **设计决策**：将 ComboWindow 分为前半段（→ 第4段普攻）和后半段（→ 鸣奏）。这比"ComboWindow 全段→第4段，Recovery→鸣奏"更符合玩家直觉——"稍晚一点按就出特殊招"是动作游戏通用语言。

**重击·余音的触发条件**：
- 鸣奏命中后，在余音窗口内短按 → 余音
- 闪避反击命中后，在余音窗口内短按 → 余音（P1，依赖闪避反击系统）
- 余音命中 → 获取尘微之声 ~40Pt

**尘微之声能量系统**：
- 上限：100Pt
- 获取：余音命中（~40Pt/次）、其他途径（P2扩展）
- 消耗：P0 阶段仅追踪不消耗，预留接口供后续大招/技能系统

### 1.3 连携链路图

```
                    ┌── ComboWindow前半段 ──→ 普攻4段 ──→ Idle
                    │
普攻1 → 普攻2 → 普攻3 ─┼── ComboWindow后半段 ──→ 重击·鸣奏 ──┬── 余音窗口短按 ──→ 重击·余音 ──→ Idle
                    │                                         │
                    └── Recovery/ComboReset ──→ 重击·鸣奏 ──┘
                                                              ↑
重击 ────────────────────────────────────────────→ 重击·鸣奏 ─┘
                                                              ↑
闪避反击（P1）───────────────────────────────────────→ 重击·余音

长按攻击键 ──→ 重击 ──┬── 短按（鸣奏窗口）──→ 重击·鸣奏 ──→ ...
                       └── 无输入 ──→ Idle
```

## 2. 输入系统改造

### 2.1 当前输入流（不改动部分）

```
HandleAttackStarted() → SetLightAttackHeld(true) + RequestLightAttack()
HandleAttackCompleted() → SetLightAttackHeld(false)
```

当前 `RequestLightAttack()` 立即触发攻击，零延迟。`SetLightAttackHeld()` 仅存储 `bLightAttackHeld`，未用于任何逻辑。

### 2.2 新输入流：Tap/Hold 检测

**核心原则**：只有从 Idle 起手时才做 Tap/Hold 判定；ComboWindow 内的输入立即路由，零延迟。

```
HandleAttackStarted():
  bLightAttackHeld = true
  LightAttackHoldElapsed = 0.0f

  if (CombatPhase != None || bCanChainFromCurrentState()) {
    // 战斗中或连携窗口内 — 立即路由，零延迟
    RequestAttack()
  } else {
    // Idle 起手 — 启动 Tap/Hold 判定
    bPendingAttackDecision = true
  }

TickComponent():
  if (bLightAttackHeld && bPendingAttackDecision) {
    LightAttackHoldElapsed += DeltaTime
    if (LightAttackHoldElapsed >= HeavyAttackHoldThreshold) {
      bPendingAttackDecision = false
      RequestHeavyAttack()
    }
  }

HandleAttackCompleted():
  bLightAttackHeld = false
  if (bPendingAttackDecision) {
    bPendingAttackDecision = false
    RequestAttack()  // 短按 → 普攻/连携路由
  }
```

### 2.3 `RequestAttack()` 路由逻辑（替代 `RequestLightAttack()`）

`RequestLightAttack()` 重命名为 `RequestAttack()`，内部根据上下文路由：

```
RequestAttack():
  if (CombatPhase == None) {
    // ── Idle 起手 ──
    if (bResonanceChainWindow && PreviousAttackType == HeavyResonance) {
      → StartHeavyEcho()
    }
    else if (bResonanceChainWindow && PreviousAttackType == DodgeCounter) {
      → StartHeavyEcho()   // P1：依赖闪避反击
    }
    else if (bResonanceTriggerWindow && PreviousAttackType == LightAttack && CurrentComboIndex == 3) {
      → StartHeavyResonance()
    }
    else if (bResonanceTriggerWindow && PreviousAttackType == HeavyAttack) {
      → StartHeavyResonance()
    }
    else {
      // 正常普攻起手/续接
      → StartLightAttack(NextComboIndex)
    }
  }
  else if (bComboWindowOpen) {
    // ── ComboWindow 内 ──
    if (CurrentComboIndex == 3 && bResonanceHalfWindow) {
      → StartHeavyResonance()  // 第3段 ComboWindow 后半段 → 鸣奏
    }
    else {
      → TransitionToNextLightAttack()  // 正常连段
    }
  }
  else {
    // ── ComboWindow 外但攻击进行中 ── 缓冲
    → BufferAttackInput()
  }
```

### 2.4 新增输入参数

| 参数 | 默认值 | 位置 | Rationale |
|------|--------|------|-----------|
| `HeavyAttackHoldThreshold` | 0.12s | `FRoverCombatSettings` | [PLACEHOLDER] 行业基准0.1-0.15s，0.12s 在体感"点击"和"按住"之间 |
| `ResonanceTriggerWindowDuration` | 0.40s | `FRoverCombatSettings` | [PLACEHOLDER] 第3段 Recovery 结束后的鸣奏触发窗口，够玩家反应 |
| `ResonanceHalfWindowNormalized` | 0.5f | `FRoverCombatSettings` | ComboWindow 归一化时间的50%之后触发鸣奏而非第4段 |
| `EchoFollowupWindowDuration` | 0.35s | `FRoverCombatSettings` | [PLACEHOLDER] 鸣奏后余音的触发窗口 |
| `ResonanceEnergyGainOnEchoHit` | 40.0 | `FRoverCombatSettings` | [PLACEHOLDER] 余音命中获取的尘微之声 |
| `MaxResonanceEnergy` | 100.0 | `FRoverCombatSettings` | 尘微之声上限 |

## 3. 状态机扩展

### 3.1 新增枚举：`ERoverAttackType`

```cpp
// RoverCombatTypes.h — 新增
UENUM(BlueprintType)
enum class ERoverAttackType : uint8
{
    None,
    LightAttack,        // 普攻1-4段
    HeavyAttack,        // 重击
    HeavyResonance,     // 重击·鸣奏
    HeavyEcho,          // 重击·余音
    DodgeCounter,       // 闪避反击（P1预留）
};
```

**Rationale**：`ERoverCombatPhase`（None/Startup/Active/ComboWindow/Recovery）描述的是单次攻击的生命周期，所有攻击类型共享。`ERoverAttackType` 描述的是"当前在打什么招"，与 Phase 正交。两者组合完整描述战斗状态。

### 3.2 状态转换矩阵

| 当前 AttackType | 当前 Phase | 输入 | 结果 |
|----------------|-----------|------|------|
| LightAttack | ComboWindow (前半) | 短按 | → LightAttack 下一段 (Startup) |
| LightAttack (idx=3) | ComboWindow (后半) | 短按 | → HeavyResonance (Startup) |
| LightAttack (idx=3) | Recovery | 短按 | → HeavyResonance (Startup) |
| LightAttack (idx=3) | None (ComboReset内) | 短按 | → HeavyResonance (Startup) |
| HeavyAttack | Recovery | 短按 | → HeavyResonance (Startup) |
| HeavyResonance | Startup/Active | 短按 | 缓冲输入，ComboWindow 开启后 → Attack01 |
| HeavyResonance | ComboWindow/Recovery | 短按 | → LightAttack Attack01 (Startup) |
| DodgeCounter | Recovery | 短按 | → HeavyEcho (Startup) [P1] |
| None | None | 长按至阈值 | → HeavyAttack (Startup) |
| LightAttack (idx=3) | Startup/Active/ComboWindow/Recovery | 按下并长按至阈值 | → HeavyResonance；即使按下时短暂续接 Attack04，阈值到达后仍由 Attack03 起始标记覆盖 |
| LightAttack (其他段) | Startup/Active/ComboWindow/Recovery | 按下并长按至阈值 | 按下先路由下一段轻击；到阈值后中断当前段 → HeavyAttack |
| 任意 | 任意 | 闪避 | → 取消当前攻击，进入闪避 |

### 3.3 组件新增状态变量

```cpp
// RoverCombatComponent.h — private 新增

ERoverAttackType CurrentAttackType = ERoverAttackType::None;
ERoverAttackType PreviousAttackType = ERoverAttackType::None;

// Tap/Hold 检测
bool bPendingAttackDecision = false;
float LightAttackHoldElapsed = 0.0f;

// 鸣奏/余音窗口计时
float ResonanceTriggerRemaining = 0.0f;   // 鸣奏触发窗口剩余时间
float EchoFollowupRemaining = 0.0f;       // 余音触发窗口剩余时间

// 尘微之声能量
float ResonanceEnergy = 0.0f;
```

### 3.4 Tick 中的窗口计时逻辑

```cpp
// TickComponent 新增（在现有 ComboReset 计时之后）：

// 鸣奏触发窗口倒计时
if (ResonanceTriggerRemaining > 0.0f)
{
    ResonanceTriggerRemaining = FMath::Max(0.0f, ResonanceTriggerRemaining - DeltaTime);
    if (ResonanceTriggerRemaining <= 0.0f)
    {
        bResonanceTriggerWindow = false;
    }
}

// 余音触发窗口倒计时
if (EchoFollowupRemaining > 0.0f)
{
    EchoFollowupRemaining = FMath::Max(0.0f, EchoFollowupRemaining - DeltaTime);
    if (EchoFollowupRemaining <= 0.0f)
    {
        bEchoFollowupWindow = false;
    }
}

// Tap/Hold 判定
if (bLightAttackHeld && bPendingAttackDecision)
{
    LightAttackHoldElapsed += DeltaTime;
    if (LightAttackHoldElapsed >= GetSettings().HeavyAttackHoldThreshold)
    {
        bPendingAttackDecision = false;
        RequestHeavyAttack();
    }
}
```

### 6.2 重击系统

**实施状态**：✅ P0-3/P0-4 已于 2026-08-08 完成。Idle 短按在释放时触发普攻，长按达到阈值触发 Attack05；Attack01/02/04 起始的连段长按仍在阈值后切入 Attack05。Attack03 起始长按已在 P0-5 改为鸣奏专用路径，不再触发 Attack05。

**Fun Hypothesis**：长按攻击键，角色后退并释放飞剑连续命中——"后退"是重击的视觉标识，让玩家在混战中清楚知道"我在打重击"。

#### 6.2.1 `RequestHeavyAttack()`

```cpp
bool URoverCombatComponent::RequestHeavyAttack()
{
    if (!CharacterOwner || bDead || bInHitReaction)
        return false;

    const bool bInterruptingLightAttack =
        CombatPhase != ERoverCombatPhase::None &&
        CurrentAttackType == ERoverAttackType::LightAttack &&
        ActiveAttackRequestId > 0;
    if (CombatPhase != ERoverCombatPhase::None && !bInterruptingLightAttack)
        return false;

    const FRoverAttackDefinition& Def = GetSettings().HeavyAttackDefinition;
    if (Def.Montage.IsNull())
        return false;

    // 起手流程与普攻一致；从轻击切入时转移移动限制，避免释放/重建产生一帧空档
    const int32 PreviousRequestId = bInterruptingLightAttack ? ActiveAttackRequestId : 0;
    AttackRequestSerial = AttackRequestSerial == MAX_int32 ? 1 : AttackRequestSerial + 1;
    const int32 RequestId = AttackRequestSerial;

    bool bMovementAccepted = PreviousRequestId > 0 &&
        CharacterOwner->TransferCombatMovementRestriction(PreviousRequestId, RequestId);
    if (!bMovementAccepted)
        bMovementAccepted = CharacterOwner->TryBeginCombatMovementRestriction(RequestId);
    if (!bMovementAccepted)
        return false;

    ActiveAttackDirection = CharacterOwner->GetActorForwardVector().GetSafeNormal2D();
    CharacterOwner->FaceCombatDirection(ActiveAttackDirection);

    ActiveAttackRequestId = RequestId;
    CurrentComboIndex = 0;  // 重击不使用 ComboIndex
    CurrentAttackType = ERoverAttackType::HeavyAttack;
    CombatPhase = ERoverCombatPhase::Startup;
    AttackWatchdogElapsed = 0.0f;
    bAttackAnimationAcknowledged = false;
    bBufferedAttackInput = false;
    bComboWindowOpen = false;
    HitActorsThisAttack.Reset();

    // 武器显隐 & 持手
    CharacterOwner->SetCombatWeaponHand(Def.WeaponHand);
    // 重击使用后退位移而非前进
    // 后退通过 StartCombatAttackAdvance 的负方向实现，或在 Character 中新增 Retreat 接口

    if (PreviousRequestId > 0)
    {
        CharacterOwner->StopCombatAttack(PreviousRequestId, ResolveAttackTransitionBlendOutTime());
        CharacterOwner->PlayCombatAttackImmediately(RequestId);
    }

    return true;
}
```

#### 6.2.2 重击后退位移

重击的后退与普攻的前冲（`AdvanceDistance`）方向相反。有两种实现方案：

**方案A（推荐）**：在 `StartAttackSegment` / `RequestHeavyAttack` 中，根据 AttackType 决定位移方向：
- LightAttack/Resonance/Echo → 前进（`AdvanceDistance`）
- HeavyAttack → 后退（`HeavyAttackRetreatDistance`）

在 `RoverCharacter::StartCombatAttackAdvance()` 中新增负距离支持，或新增 `StartCombatAttackRetreat()` 方法。

**方案B**：在重击 Montage 的 AnimNotify 中触发后退，通过 Root Motion 或 Motion Warping 实现。

> **推荐方案A**：与现有前进位移机制一致，通过 `StartCombatAttackAdvance(RequestId, -RetreatDistance, RetreatDuration)` 传入负值实现后退。需要在 `RoverCharacter::StartCombatAttackAdvance()` 中验证负距离是否正确处理（可能需要取绝对值并反转方向）。

#### 6.2.3 重击的武器Trace

重击的武器Trace复用现有 `PerformWeaponTrace()` 逻辑，无改动。Trace 参数从 `HeavyAttackDefinition` 读取（TraceRadius/TraceSampleCount 等）。

如果重击包含飞剑（原版有飞剑连续命中），需确认 AM_Attack05 动画中武器是否脱手。如果脱手，复用 Attack03 的飞剑系统，但锚点位置和旋转参数不同。

> **P0 简化**：先不实现重击飞剑，只做手持武器的近身Trace。飞剑作为 P1 增强。

### 6.3 重击·鸣奏

**实施状态**：✅ P0-5 已于 2026-08-08 完成。Attack03 前半窗口继续 Attack04，后半窗口和 Recovery 可进入鸣奏；从 Attack03 开始的长按达到阈值也直接进入鸣奏，不再触发 Attack05。Attack05 Recovery 与自然结束后的 `0.40s` 窗口仍可进入鸣奏；鸣奏后的攻击输入接回 Attack01。

**实际方案**：采用独立 `URoverAnimNotifyState_ResonanceWindow`，不从 Python 或 Tick 推算 Montage 播放百分比。`ResonanceHalfWindowNormalized=0.50` 表示从 Attack03 的 ComboWindow 起点到动画末尾再取 50%，当前 Attack03 的 ComboWindow 起点为 `0.50`，所以鸣奏窗口从整段动画 `0.75` 处开始。

**Fun Hypothesis**：玩家在第三段后稍停一下再按攻击，角色突进刺击——"等待"本身就是策略决策，不是手速测试。

#### 6.3.1 触发条件

鸣奏有三种触发路径：

| 路径 | 前置条件 | 触发时机 |
|------|---------|---------|
| A: 第3段普攻后 | CurrentAttackType==LightAttack, CurrentComboIndex==3 | ComboWindow 后半段短按，或 Recovery 期间短按，或 ComboReset 期间短按 |
| A2: 第3段长按 | 攻击输入从 LightAttack idx=3 开始 | 达到 HeavyAttackHoldThreshold 后直接进入鸣奏 |
| B: 重击后 | CurrentAttackType==HeavyAttack | Recovery 期间短按，或 ComboReset 期间短按 |
| C: 闪避反击后 | CurrentAttackType==DodgeCounter | Recovery 期间短按 [P1] |

#### 6.3.2 鸣奏触发窗口的开启

在 `CompleteAttackSegment()` 或 `FinishAttack()` 中，当完成的是第3段普攻或重击时，开启鸣奏触发窗口：

```cpp
void URoverCombatComponent::CompleteAttackSegment(int32 RequestId)
{
    // ... 现有逻辑 ...

    // 新增：开启鸣奏触发窗口
    if (CurrentAttackType == ERoverAttackType::LightAttack && CurrentComboIndex == 3)
    {
        bResonanceTriggerWindow = true;
        ResonanceTriggerRemaining = GetSettings().ResonanceTriggerWindowDuration;
        PreviousAttackType = CurrentAttackType;
    }
    else if (CurrentAttackType == ERoverAttackType::HeavyAttack)
    {
        bResonanceTriggerWindow = true;
        ResonanceTriggerRemaining = GetSettings().ResonanceTriggerWindowDuration;
        PreviousAttackType = CurrentAttackType;
    }
}
```

#### 6.3.3 ComboWindow 后半段鸣奏路由

在 `RequestAttack()` 的 ComboWindow 分支中添加后半段判断：

```cpp
if (bComboWindowOpen)
{
    // 第3段 ComboWindow 后半段 → 鸣奏
    if (CurrentAttackType == ERoverAttackType::LightAttack &&
        CurrentComboIndex == 3 &&
        GetComboWindowProgressNormalized() >= GetSettings().ResonanceHalfWindowNormalized)
    {
        return StartHeavyResonance(ResolveAttackInputDirection());
    }

    // 正常连段
    bBufferedAttackInput = false;
    return TransitionToNextAttack(ResolveAttackInputDirection());
}
```

> **注意**：需要新增 `GetComboWindowProgressNormalized()` 方法来获取 ComboWindow 的归一化进度。这需要 AnimInstance 提供当前 Montage 播放进度，或由 ComboWindow 的 NotifyState 记录开始时间。

**简化方案**：如果获取 ComboWindow 内的精确进度太复杂，可以用时间差替代——在 `BeginComboWindow()` 时记录 `ComboWindowOpenTime`，在 `RequestAttack()` 中计算 `(WorldTime - ComboWindowOpenTime) / ComboWindowDuration`。但 `ComboWindowDuration` 当前不是固定值，是由 NotifyState 定义的区间。

**更简单的方案**：将第3段的 ComboWindow NotifyState 拆成两个——前半段是 `RoverAttackComboWindow`（→ 第4段），后半段是 `RoverAttackResonanceWindow`（→ 鸣奏）。这样不需要计算归一化进度，AnimNotify 直接路由。

> **推荐**：使用拆分 NotifyState 的方案。在 Montage 中：
> - 帧 X → 帧 Y：`RoverAttackComboWindow`（前半段，允许第4段）
> - 帧 Y → 帧 Z：`RoverAttackResonanceWindow`（后半段，允许鸣奏）
> - 帧 Z 之后：Recovery（允许鸣奏，由 ResonanceTriggerRemaining 计时）

#### 6.3.4 `StartHeavyResonance()`

```cpp
bool URoverCombatComponent::StartHeavyResonance(const FVector& AttackDirection)
{
    const FRoverAttackDefinition& Def = GetSettings().HeavyResonanceDefinition;
    if (Def.Montage.IsNull())
        return false;

    // 起手流程与重击类似，但使用突进位移
    AttackRequestSerial = AttackRequestSerial == MAX_int32 ? 1 : AttackRequestSerial + 1;
    const int32 RequestId = AttackRequestSerial;

    // 鸣奏可以取消当前攻击的 Recovery
    if (ActiveAttackRequestId > 0)
    {
        CancelAttack(ActiveAttackRequestId, Def.MontageBlendInTime);
    }

    if (!CharacterOwner->TryBeginCombatMovementRestriction(RequestId))
        return false;

    ActiveAttackDirection = AttackDirection.GetSafeNormal2D();
    if (ActiveAttackDirection.IsNearlyZero())
        ActiveAttackDirection = CharacterOwner->GetActorForwardVector().GetSafeNormal2D();
    CharacterOwner->FaceCombatDirection(ActiveAttackDirection);

    ActiveAttackRequestId = RequestId;
    CurrentComboIndex = 0;
    CurrentAttackType = ERoverAttackType::HeavyResonance;
    CombatPhase = ERoverCombatPhase::Startup;
    AttackWatchdogElapsed = 0.0f;
    bAttackAnimationAcknowledged = false;
    bBufferedAttackInput = false;
    bComboWindowOpen = false;
    HitActorsThisAttack.Reset();

    // 关闭鸣奏触发窗口
    bResonanceTriggerWindow = false;
    ResonanceTriggerRemaining = 0.0f;

    CharacterOwner->SetCombatWeaponHand(Def.WeaponHand);

    // 突进位移（前进）
    CharacterOwner->StartCombatAttackAdvance(
        RequestId, GetSettings().ResonanceDashDistance, GetSettings().ResonanceDashDuration);

    return true;
}
```

## 14. 附录：完整 RequestAttack() 路由伪代码

```cpp
bool URoverCombatComponent::RequestAttack()
{
    if (!CharacterOwner || bDead || bInHitReaction)
        return false;

    // ── Idle 状态（CombatPhase == None）──
    if (CombatPhase == ERoverCombatPhase::None)
    {
        // 余音窗口（鸣奏后/闪避反击后）
        if (bEchoFollowupWindow)
        {
            if (PreviousAttackType == ERoverAttackType::HeavyResonance ||
                PreviousAttackType == ERoverAttackType::DodgeCounter)
            {
                return StartHeavyEcho(ResolveAttackInputDirection());
            }
        }

        // 鸣奏窗口（第3段后/重击后）
        if (bResonanceTriggerWindow)
        {
            if ((PreviousAttackType == ERoverAttackType::LightAttack && PreviousComboIndex == 3) ||
                PreviousAttackType == ERoverAttackType::HeavyAttack)
            {
                return StartHeavyResonance(ResolveAttackInputDirection());
            }
        }

        // 正常普攻起手/续接
        const int32 AttackCount = GetLightAttackCount();
        const bool bContinueCombo = PreviousComboIndex >= 1 && ComboResetRemaining > 0.0f;
        const int32 NextComboIndex = bContinueCombo && AttackCount > 0
            ? (PreviousComboIndex >= AttackCount ? 1 : PreviousComboIndex + 1)
            : 1;
        return StartLightAttackSegment(NextComboIndex, ResolveAttackInputDirection());
    }

    // ── ComboWindow 内 ──
    if (bComboWindowOpen)
    {
        // 第3段 ComboWindow 后半段 → 鸣奏
        if (bResonanceHalfWindow &&
            CurrentAttackType == ERoverAttackType::LightAttack &&
            CurrentComboIndex == 3)
        {
            return StartHeavyResonance(ResolveAttackInputDirection());
        }

        // 正常连段；第四段由 TransitionToNextAttack() 回绕第一段
        bBufferedAttackInput = false;
        AttackInputBufferRemaining = 0.0f;
        BufferedAttackDirection = FVector::ZeroVector;
        return TransitionToNextAttack(ResolveAttackInputDirection());
    }

    // ── ComboWindow 外但攻击进行中 ── 缓冲
    if (CurrentComboIndex > 0 || CurrentAttackType != ERoverAttackType::None)
    {
        bBufferedAttackInput = true;
        BufferedAttackDirection = ResolveAttackInputDirection();
        AttackInputBufferRemaining = FMath::Max(0.0f, GetSettings().AttackInputBufferDuration);
        return true;
    }

    return false;
}
```

```
  None → [Request*] → Startup → [AcknowledgeAttackStarted] → Active

       → [FinishAttack] → None
                                       ↓
                              CompleteAttackSegment():
                                ├─ LightAttack idx=3 → 开启鸣奏窗口
                                ├─ HeavyAttack → 开启鸣奏窗口
                                ├─ HeavyResonance → 无输入则自然结束；有输入则在窗口内回 Attack01
                                └─ 其他 → 关闭所有窗口
```

## 16. 跳跃攻击（AirAttack）

### 16.1 玩法规则

- 角色处于 `CharacterMovement::IsFalling()` 且当前没有其他攻击时，按攻击键立即进入 `AirAttack`，不经过地面 Tap/Hold 判定。
- 跳跃攻击使用动作库中的 `AM_AirAttack_Start / Loop / End`：起手播放 Start，随后 Loop Section 自循环；角色落地时立即跳到 End Section 播放落地斩。
- AirAttack 使用独立 `ERoverAttackType::AirAttack` 和 `FRoverAttackDefinition`，不占用 `LightAttackChain`，不会推进或继承地面四连 ComboIndex。
- `RoverAttackStarted` 确认后按 `AirAttackAscentHeight` 计算向上初速度；`AirAttack_Start` 源动画第 `AirAttackApexFrame` 帧触发 `RoverAirAttackApex`，在峰值处切入俯冲。
- `RoverAttackStarted` 确认后立即开启武器 Trace，覆盖低空快速落地和高空 Loop 两种情况；End 内的 ActiveEnd / Recovery / Finished 负责关闭判定、释放移动限制和自然收招。
- AirAttack 落地期间屏蔽普通 Light/Heavy/Roll 落地动画，由 End Montage 全身接管；Montage 完成后回到现有 Grounded 动画状态。
- 闪避、受击、死亡、Montage 拒绝和 watchdog 仍走统一取消路径，保证武器隐藏、Trace 关闭、移动限制释放。

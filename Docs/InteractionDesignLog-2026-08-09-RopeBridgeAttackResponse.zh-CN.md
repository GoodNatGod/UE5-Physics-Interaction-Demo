# 交互设计复盘 | 吊桥攻击响应分层

> 日期：2026-08-09
>
> 主题：保留桥上攻击位移，同时让落地稳定强于普通攻击
>
> 结果：Attack / Landing 线速度比由 `1.011` 降至 `0.514`，专项自动门槛通过

## 1. 玩家反馈

玩家在桥上走路时桥面反馈基本正常，但普通攻击会让整座桥产生接近甚至超过跳跃落地的剧烈晃动。

这个问题有两个不能回避的体验要求：

1. 桥上攻击仍要有向攻击方向的位移，不能因为脚下是动态物体就把招式改成原地挥刀；
2. 普通攻击不应该拥有接近落地的整桥能量，玩家必须能从桥面反馈中分辨“挥刀”和“身体落下”。

因此目标不是简单让桥少动，而是建立正确的行为层级：

```text
站立 < 行走 < 奔跑 < 普通攻击 < 真实落地
```

其中攻击和落地不只强度不同，方向语义也不同：攻击是水平推进与局部直击，落地是由下坠速度产生的垂直冲击。

## 2. 问题演进

### 2.1 初始倒挂

早期专项记录：

| 行为 | 桥体线速度峰值 |
|---|---:|
| Attack01 | `259.5cm/s` |
| Landing | `119.7cm/s` |

当时落地本身也偏弱。落地帧的 CharacterMovement 已经清理了部分垂直速度，桥无法读取真实接触前下坠速度。

### 2.2 落地增强后仍接近持平

修正下落速度保存和落地冲量后：

| 行为 | 桥体线速度峰值 |
|---|---:|
| Attack01 | `303.6cm/s` |
| Landing | `300.2cm/s` |

落地反馈明显增强，但攻击也随约束链状态波动升高。此时可以确认问题不只是“落地参数太小”，而是攻击存在独立的载荷传递。

### 2.3 最终结果

最新专项连续执行两次 Attack01，并取更差的一次：

| 指标 | 当前结果 |
|---|---:|
| Attack01 第一次 | `131.6cm/s / 128.7deg/s` |
| Attack01 第二次 | `158.8cm/s / 193.3deg/s` |
| Attack 最大线速度 | `158.8cm/s` |
| Landing 线速度 | `309.2cm/s` |
| Attack / Landing | `0.514` |
| 桥上相对推进 | `18.7cm` |

## 3. 诊断方法

专项在 Attack01 的 Startup、Active、Recovery 和结束后持续采样：

- 全桥最大线速度和角速度；
- 峰值木板索引与角色脚下木板索引；
- 武器 Trace 是否开启；
- 世界交互请求增量；
- 动画 Root Motion 是否存在；
- CharacterMovement InitialPush / Push / StandingDownwardForce；
- 吊桥周期 Movement Impulse；
- 角色相对脚下板的前向位移；
- 攻击推进 Root Motion Source 是否存在；
- 攻击结束后物理参数和桥板阻尼是否恢复。

诊断结果显示，旧峰值主要发生在 Attack Recovery 或约束链延迟响应期，而不是武器有效命中帧。峰值可以在 `trace=false`、World Interaction 没有增量、Push Force 为零时出现。

这说明主要矛盾是：

> 角色通过 Movement Base 推进时，水平位移会改变角色与多块桥板之间的承重点；载荷变化经过 60 板约束链传播，形成延迟的线速度和角速度峰值。

## 4. 被否决的方案

### 4.1 攻击推进归零

优点是能快速降低桥体响应，缺点是角色在桥上和静态地面的招式手感不一致。用户明确要求桥上攻击保留位移，因此该方案回退。

### 4.2 攻击时降低角色重量

降低 `StandingDownwardForceScale` 会让攻击开始时桥面突然卸载，结束后再恢复重量，反而可能制造新的回弹。它也让“100kg 角色站在桥上”的物理语义失真。

最终站立载荷保持 `1.0`。

### 4.3 只降低通用攻击冲量

通用冲量同时服务木箱、普通刚体和其他环境对象。为了稳定吊桥而降低它，会直接破坏“一刀破箱”和普通物体受击方向。

这暴露了真正的架构问题：接收者需要拥有自己的物理响应语义。

### 4.4 永久提高吊桥阻尼

全局提高 `LinearDamping / AngularDamping` 可以压低攻击峰值，但也会让走路、奔跑、跳跃和落地失去差异。动态桥会退化成一条缓慢回弹的硬地面。

最终只在攻击推进窗口临时提高阻尼。

### 4.5 清空完整速度

攻击推进结束时若清空包括 Z 在内的完整速度，角色跨过板缝短暂失去支撑时会出现悬停，随后重新接触桥板形成二次下压。

最终攻击推进忽略 Z 累积，只清理由推进产生的水平残速。

## 5. 语义拆分

### 5.1 动态底座推进

职责：保留招式位移，同时控制载荷转移速率。

静态地面保留原有 `MoveToForce`。模拟底座改用 `ConstantForce`：

- 距离缩放 `0.55`；
- 时长缩放 `2.50`；
- Ease `1.0`；
- 平滑曲线做积分归一化，改变速度分布但不丢失目标总位移；
- `IgnoreZAccumulate` 保留重力；
- 结束时 `ClampVelocity=0` 清水平推进残速。

### 5.2 CharacterMovement 物理推力

职责：处理角色胶囊阻挡模拟物体时的引擎原生推力。

- 攻击期间 Push Scale 为 `0.0`；
- Standing Downward Force 保持 `1.0`；
- 攻击若从静态地面进入模拟桥板，在 Movement Base 改变的 Tick 立即补启用隔离；
- 攻击结束后按原恢复逻辑恢复角色物理参数。

### 5.3 桥板 DirectHit

职责：表达武器真实打到木板时的局部响应。

`AWorldRopeBridge` 作为 `UPhysicsInteractable` 自行处理 DirectHit：

- `DirectHitImpulseScale=0.05`；
- `MaximumDirectHitImpulse=50`；
- 冲量施加在真实 Impact Point；
- 接收者声明已处理物理冲量后，Subsystem 跳过同一 Actor 的通用施力。

这组参数不影响木箱。

### 5.4 木箱与普通环境物

职责：保持通用武器受击语义。

木箱继续使用原有伤害、破裂和定向冲量。此次吊桥修复没有降低木箱攻击强度，也没有改变 Geometry Collection 破裂参数。

### 5.5 Explosion

职责：表达范围事件。

Explosion 继续走通用径向冲量，不复用桥板 DirectHit 上限。当前只完成路径隔离，吊桥爆炸稳定性将作为单独测试项。

## 6. 战斗阻尼窗口

攻击推进仍会真实改变承重点，因此桥自身需要一个只服务战斗载荷转移的短时耗散窗口：

| 参数 | 当前值 |
|---|---:|
| Linear Damping Multiplier | `4.0` |
| Angular Damping Multiplier | `6.0` |
| Advance 结束后的 Grace | `1.0s` |

窗口覆盖两段时间：

1. 角色攻击推进正在作用；
2. 推进结束后，能量仍沿约束链传播的余量期。

窗口结束后，每块桥板恢复基础 `1.5 / 4.0` 阻尼。自动化会同时检查“确实启用”和“按时恢复”，避免一次参数修改让桥永久处于战斗阻尼。

## 7. 自动化如何约束手感

此次专项不再满足于记录峰值后仍输出通过，而是增加体验失败门槛：

| 设计意图 | 自动化门槛 |
|---|---|
| 攻击明显弱于落地 | 两次 Attack 取最大值，Attack / Landing `<=0.75` |
| 攻击不能让宽桥剧烈翻滚 | Attack 角速度 `<=280deg/s` |
| 桥上仍保留招式推进 | 相对前向位移 `>=15cm` |
| 攻击推进不能伪装成脚步 | 额外 Movement Impulse `<=0.01` |
| 不能靠减轻角色重量稳定 | Standing Force 必须保持 `1.0` |
| 临时稳定不能变成永久状态 | Combat Damping 必须启用并恢复 |
| 修复不能破坏桥的最终状态 | 离桥速度 `0/0`，自然角误差 `<=2deg` |

最新值 `0.514` 距离 `0.75` 门槛保留了约 31% 的相对裕量，能降低后续小幅手调重新倒挂的概率。

## 8. 策划调参边界

三个主要入口分别负责不同问题：

| 调参入口 | 负责什么 | 不应该负责什么 |
|---|---|---|
| `DA_RoverMovementConfig -> Combat|Dynamic Base` | 桥上攻击距离、时长和速度分布 | 武器伤害、木箱破裂 |
| `DA_WorldInteractionConfig -> Rope Bridge -> Character Load|Combat` | 攻击载荷经过桥体时的耗散 | 走、跑、跳的全局阻尼 |
| `DA_WorldInteractionConfig -> Rope Bridge -> Interaction|Direct Hit` | 刀刃真实命中桥板的局部冲量 | Explosion、木箱和普通刚体 |

推荐调参顺序：

1. 先确定桥上攻击至少保留多少相对位移；
2. 用 Duration 和 Ease 控制载荷输入速度；
3. 再用战斗阻尼倍率限制约束链峰值；
4. 单独调整 DirectHit 的局部可见度；
5. 最后复跑两次攻击、落地和离桥恢复专项。

## 10. 对外表达

面试时可以这样概括：

> 玩家要求桥上攻击保留位移，但普通攻击不能让吊桥比落地更晃。我先用帧级采样排除了武器碰撞、世界请求、动画 Root Motion、CharacterMovement Push 和额外脚步冲量，确认主要来源是动态 Movement Base 上的载荷转移。
>
> 我没有通过取消位移或降低角色重量掩盖问题，而是把动态底座推进、桥板 DirectHit、木箱通用冲量和 Explosion 拆成独立通道。推进改用平滑 ConstantForce，桥只在战斗窗口提高阻尼，DirectHit 由桥接收者自行限幅。最终攻击仍前移 18.7cm，最大桥体速度降到落地的 51.4%，并用两次 Attack01 和明确失败阈值防止后续串扰。

这个案例想证明的不是“会调 Physics Constraint”，而是能够把玩家行为、物理能量来源、参数所有权和自动化验收放在同一个设计闭环中。

# 鸣潮水面复刻实现方案 — 视觉拆解 + UE5.8 落地规格

> **用途**：Codex 实现"鸣潮式可交互水面"的视觉规格文档。先读 §1 拆解鸣潮水面由哪些视觉元素构成，§2 给每个元素的 UE5.8 实现手段与参数目标，§3 是可执行的 P0 材质规格，§4 是涟漪交互规格。
> **配套文档**：材质与涟漪选型沿用《可交互水面调研文档.md》。主 Demo 使用场景现有的 1 个 WaterZone + 2 个 WaterBodyLake，并由 WaterAdvanced 浅水子系统驱动；独立 `L_WaterP0` 仍保留 StaticMesh + 自制 RT 作为兼容验证后端。
> **项目**：鸣潮复刻（UE 5.8，写实 PBR 渲染路线，单人第三人称动作）
> **版本**：0.4.0 · 2026-08-10（WaterAdvanced 双 Lake 版）
> **事实标注**：`[已知]` = 公开报道/实机可证；`[推断]` = 基于实机观察与 UE 通用技术栈的合理推测，实现时无需求证，但不得写入交付口径。

## 0. 先给结论

鸣潮水面 = **写实 PBR 基底 + 二次元向通透调校 + 强角色交互反馈**，由 8 个可独立复刻的视觉元素构成：

| # | 视觉元素 | 鸣潮实机表现 | 复刻优先级 |
|---|---------|------------|:--:|
| 1 | 深度吸收双色 | 浅水通透见底偏暖绿，深水转冷蓝变暗 | **P0** |
| 2 | 镜面反射 | 天空/山体/建筑倒影清晰，风平浪静时镜面感强 | **P0** |
| 3 | 岸线/障碍物泡沫 | 岸边白沫带，石头桥墩边缘聚集 | **P0** |
| 4 | 法线扰动 + 微起伏 | 水面细碎波光，非绝对平面 | **P0** |
| 5 | 焦散（浅水底部光斑） | 浅水区水底波光粼粼 | P0 |
| 6 | 角色交互涟漪 | 涉水脚下涟漪圈、低空飞行气流波（2.4 重点优化 `[已知]`） | **P0** |
| 7 | 入水/出水水花 | 跳入水花粒子 + 大涟漪，游泳划水波纹 | P1 |
| 8 | 湿身效果 | 出水后服装通透、水流附着（泳装时装系统 `[已知]`） | P2（远期可选） |

> 2.4 版本官方对水体做了大幅度优化：水面战斗、行走、贴近水面飞行均有对应水波反馈 `[已知]`（玩家社区评价"1.0 被吐槽有潮字没潮水，2.4 把潮做出来了"）。**交互反馈是鸣潮水面的灵魂，材质只是底子**——复刻时交互优先级不低于材质。

## 1. 鸣潮水面视觉拆解（逐元素）

### 1.1 深度吸收双色 `[推断，实机可验证]`

**观察点**：站在浅水区看脚下——水是透明的，能看到水底泥沙，颜色偏暖（阳光透射）；走向深水，颜色逐渐变冷、变暗、最后不透底。

**技术构成推断**：材质内 `SceneDepth - PixelDepth` 求水深，用深度值在"浅水色/深水色"之间 Lerp。鸣潮的调校偏向**浅水更通透、深水更青蓝**（二次元向写实），不是写实海洋那种深黑蓝。

**复刻关键**：
- 双色不是美术死值，是"深度吸收系数"驱动的连续过渡；
- 浅水色要带暖调（阳光感），深水色带冷调（青蓝）；
- 透明度从"完全见底"到"完全不透"的过渡要快（鸣潮浅水区很浅就能见底，深水区 1-2m 就看不见底）。

### 1.2 镜面反射 `[推断]`

**观察点**：风平浪静的水面倒映天空和岸边建筑，反射很清晰，几乎像镜子；水面微动时倒影轻微扭曲。

**技术构成推断**：UE4 魔改 + 反射方案（大概率 SSR/平面反射组合）。鸣潮水面反射感强于多数写实游戏——这是二次元向写实的共同特征（水面要"干净"）。

**复刻关键**：
- 项目已启用 Lumen，`Single Layer Water` 模式下 Lumen 反射强制为镜面反射（官方已知行为）——**正好匹配鸣潮的镜面感**，不是 bug 是特性；
- 反射强度要按视角调：俯视时反射弱（看到的是水底），平视时反射强（看到的是倒影）——用 Fresnel 控制。

### 1.3 岸线/障碍物泡沫 `[推断]`

**观察点**：岸边有一圈白色泡沫带，宽度均匀；石头、桥墩、木箱入水处有白色聚集；角色涉水走过时脚下短暂泛白。

**技术构成推断**：泡沫 mask = 浅水区（深度 < 阈值）+ 边缘（距最近水面距离小），叠加噪点纹理做碎裂感，双方向平移产生流动。

**复刻关键**：
- 泡沫是"边缘现象"不是"整片白"——mask 要窄、要碎（噪点扰动）、要随水面微动；
- 鸣潮泡沫偏"细碎白沫"，不是写实海洋的大浪白沫；
- 泡沫宽度可参数化（岸线宽 vs 障碍物宽可分开调）。

### 1.4 法线扰动 + 微起伏 `[推断]`

**观察点**：水面不是完全平的，有细碎的波光在闪动；但整体波动幅度很小，湖面平静。

**技术构成推断**：双层法线贴图平移（大尺度慢速 + 小尺度快速）叠加出波光，配合极小振幅 WPO（1-2cm 正弦）让几何有微起伏。

**复刻关键**：
- 两层法线的速度/方向/强度分别调——鸣潮的波光是"细碎高频"，大尺度层强度要低；
- WPO 振幅克制（≤2cm），只加"活水感"，不加"浪"；
- 法线强度决定反射扭曲度：鸣潮反射清晰 → 法线扰动整体偏弱。

### 1.5 焦散 `[推断]`

**观察点**：浅水区的水底有波光粼粼的光斑，随水面波动移动。

**技术构成推断**：Voronoi 噪点 + 平移 + 投影到水下物体表面（鸣潮浅水区水底清晰可见，焦散是重要细节）。

**复刻关键**：
- SLW 模式自带焦散支持（材质里有 Caustics 相关输入/参数），优先用官方通道；
- 焦散只在水浅的区域可见（深度 mask），深水区自动消失；
- 强度克制（0.2-0.4），鸣潮是"波光"不是"亮瞎"。

### 1.6 角色交互涟漪 `[已知存在，技术构成推断]`

**观察点**：2.4 版本后——走路踩水，脚下持续有小涟漪圈扩散；冲刺更明显；低空飞行掠过水面有气流波痕；攻击打水有水波脉冲。

**技术构成推断**：交互点写入高度场（RT 波动方程，业界标准做法）或 Niagara 涟漪粒子，材质把高度转法线叠加到水面。

**复刻关键**：
- 涟漪要**持续跟随**（走一步出一步），不是一次性事件——这是"踩水感"的核心；
- 涟漪形态：环形、由中心向外扩散、振幅衰减、半径增长后消失；
- 移动速度映射强度：走 < 跑 < 冲刺（与地表杂物系统的反馈分级语言一致，两个系统共享"速度→强度"的语义）。

### 1.7 入水/出水水花 `[已知存在，技术构成推断]`

**观察点**：跳入水中，落点溅起水花 + 一圈大涟漪；游泳划水有水波；出水时带起水流。

**复刻关键**：
- 水花 = Niagara 粒子（飞溅小滴 + 柱状水花），强度由入水速度映射；
- 大涟漪 = 一次性强写入 RT 激波；
- 水花颜色要带水面主色（半透明白），不能是纯白贴纸。

### 1.8 湿身效果 `[已知，远期可选]`

**观察点**：泳装时装下水后服装变清透、水流附着、坐家具留水渍。

**复刻关键**：这是角色材质系统（参数切换 + 水珠法线 + 环境水渍），不是水面系统。**P2 前不碰**，仅记录为远期扩展点。本项目若做，建议简化为"出水后材质参数混合 0.5s 淡入淡出"。

## 2. 复刻技术路线（选型沿用调研文档）

```
`BP_Waterplane`（纯 StaticMesh 承载）+ 自制材质（§3）+ 自制涟漪交互（§4）
```

| 层 | 方案 | 说明 |
|----|------|------|
| 水体放置 | 场景现有 `BP_Waterplane`（Engine Plane） | 不使用 Water Brush，不修改 Landscape；Actor Transform 直接控制位置与大小 |
| 水面渲染 | 自制 `M_RoverWater`（SLW 或 Translucent，见 §3） | 对标鸣潮 8 个视觉元素中的 1-5 |
| 涟漪交互 | RT 波动方程（§4）+ Niagara 水花粒子 | 对标视觉元素 6-7 |
| 游泳 | 水体积触发既有 `MOVE_Swimming` 状态链路 | P1，项目已预留状态 |
| 元素反应 | `WorldInteractionSubsystem` 注册水面 Receiver | P2，`EWorldElementType::Water` 已存在 |
| 浮力 | `BuoyancyComponent` 挂 `PhysicsInteractable` | P2 |

**与《可交互水面调研文档》的分工**：调研文档 §6 给了插件启用、目录、C++ 组件和涟漪模拟核心；本文档 §3-§4 补"材质视觉目标 → 节点实现"和"涟漪交互规格"，两者合并即为完整实现输入。

## 3. P0 水面材质实现规格（对标元素 1-5）

### 3.1 主材质 `M_RoverWater`（SLW 路线，推荐）

```
Blend Mode    = Opaque（SLW 在 Opaque 域，靠 SceneColor 计算透明度）
Shading Model = SingleLayerWater
```

**节点网络（按视觉元素分组）**：

| 视觉元素 | 材质输入 | 节点构成 |
|---------|---------|---------|
| 1 深度双色 | `WaterColor`、`WaterOpacity` | `SceneDepth - PixelDepth` = 水深 → `DepthFade`：Lerp(浅水色 0.55,0.72,0.78 / 深水色 0.08,0.22,0.32, 1-exp(-Absorption×水深))；Absorption [PLACEHOLDER: 2.5/m]；Opacity 同水深驱动，浅水 0.15、深水 1.0 |
| 2 反射 | `Refraction`（弱）、法线（弱） | 依赖法线扰动强度；Fresnel 控制反射/折射权重（平视镜面、俯视透底） |
| 3 泡沫 | `WaterScatteringCoefficients` 或材质内叠加（Translucent 路线则 Emissive 加白） | 泡沫 mask = 深度 < 15-30cm 的窄带 + `DistanceToNearestSurface` 边缘 → 噪点纹理（Tiling 4，双 Panner 0.02/0.03）→ 与深度 mask 相乘；泡沫白 0.9,0.95,1.0 |
| 4 法线扰动 | `Normal` | 双层：大尺度法线 Panner(0.05,0.02)×0.5 + 小尺度法线 Panner(-0.08,0.04)×0.8，`Normalize` 叠加；整体强度系数 [PLACEHOLDER: 0.6] |
| 4 WPO 起伏 | `WorldPositionOffset` | 小振幅正弦：`sin(WorldPos.x×0.02 + Time×0.8)×1.0cm + sin(WorldPos.y×0.015 - Time×0.6)×1.0cm`；振幅 [PLACEHOLDER: 1.5cm] |
| 5 焦散 | 焦散通道（SLW 自带）或自定义投影 | Voronoi 噪点（Tiling 6）× Panner(0.03,0.01) → 深度 mask（水深 < 80cm）→ 乘强度 [PLACEHOLDER: 0.3]；SLW 下走 `Caustics` 相关参数优先 |

**参数全部暴露为 MI 参数**（`MI_RoverWater_Lake` 调参，数值进 `DA_RoverWaterConfig` 记录默认值）：`ShallowWaterColor / DeepWaterColor / WaterAbsorption / FoamWidth / FoamIntensity / NormalStrength / NormalSpeedA/B / WpoAmplitude / CausticsIntensity / CausticsDepthLimit`。

### 3.2 材质函数 `MF_RoverRipple`（涟漪叠加，§4 联动）

```
输入：RT 高度场采样（世界坐标→RT UV 反算）+ 强度缩放
输出：Normal 增量（HeightToNormal，采样 4 邻域）+ 可选泡沫增量（高度>阈值处泛白）
```

在 `M_RoverWater` 的 Normal 组末尾与 §3.1 第 4 项叠加：`BlendAngleCorrectedNormals(双层法线, RippleNormal × RippleStrength)`。

### 3.3 明确不做

- 大浪 Gerstner（鸣潮湖面平静，不需要）；
- 卡通色阶（本项目写实路线）；
- 无限海洋和 WaterBody 地形雕刻（本 Demo 使用局部平面水片）。

## 4. P0 涟漪交互实现规格（对标元素 6）

### 4.1 高度场模拟（RT ping-pong 波动方程）

沿用调研文档 §6.4 的核心，补视觉规格：

| 参数 | 目标 | Rationale |
|------|------|-----------|
| RT 分辨率 | 512×512 | 角色周围 20m 区域，1 像素 ≈ 4cm，涟漪细节足够 |
| 跟随方式 | P0 使用固定 20m × 20m 水波域；P1 再评估移动 RT | 固定域没有重定位接缝，适合先验证池塘级交互闭环 |
| 波动传播 | 四邻平均 ×2 − 上帧 − 衰减 | 标准 2D 波动方程，环形扩散 |
| 衰减系数 | [PLACEHOLDER: 0.98/帧] | 决定涟漪消失速度：太慢水花常驻，太快涟漪不可见 |
| 交互写入 | `DrawMaterialToRenderTarget(M_RoverRippleWrite, 位置/强度)` | 脚踩/落水/攻击共用写入通道 |

### 4.2 交互触发表（与地表杂物系统共享"速度→强度"语义）

| 触发 | 条件 | 写入强度 | 频率 |
|------|------|---------|------|
| 涉水行走 | 脚在水面 ±15cm 内 | [PLACEHOLDER: 0.3] | 每 0.25s（`WalkRippleInterval`） |
| 涉水奔跑 | 同上，速度映射 | [PLACEHOLDER: 0.5] | 每 0.15s |
| 入水（跳/冲刺入水） | ImpactSpeed > 阈值 | [PLACEHOLDER: 1.0] + 额外大半径环 | 一次性，触发 Niagara 水花 |
| 攻击命中水面 | 武器 Trace 打到 SurfaceType5(Water) | [PLACEHOLDER: 0.6] | P1 |
| 低空飞行掠过（可选） | 飞行高度 < 30cm 且速度 > 阈值 | [PLACEHOLDER: 0.4] | P2，参考鸣潮 2.4 气流波痕 |

### 4.3 涟漪视觉验收对照（以鸣潮实机为参照）

- 走一步出一圈涟漪，圈径先扩大后消失，无残留抖动；
- 涟漪振幅衰减平滑（无"水花在转圈"的持续能量）；
- 奔跑涟漪明显强于行走但同形态（不是两种特效）；
- 涟漪与水材质融合（高度转法线，不是贴纸圈）；
- 入水瞬间：水花粒子 + 大涟漪 + 短暂泛白，0.5s 内恢复平静。

## 5. P1：游泳与攻击水花

| 功能 | 实现 | 说明 |
|------|------|------|
| 游泳 | 水体积（PhysicsVolume 或 WaterBody 触发）→ 既有 `MOVE_Swimming` 状态链路 | `RoverLocomotionTypes.h` 已预留 `Swimming`；深水自动切换、浅水回 Grounded |
| 划水波纹 | 游泳时按划水频率写入涟漪（复用 §4 通道） | 强度低于入水，持续低频 |
| 攻击水花 | 武器 Trace 命中 SurfaceType5(Water) → Spawn `NS_RoverWaterSplash` + 涟漪脉冲 | Trace 已能识别 Physical Material；复用战斗→交互请求链路 |

## 6. P2：元素反应与浮力（简要）

- **元素反应**：水面注册为 `WorldInteractionSubsystem` 的 Receiver——火元素 Request → 蒸汽 Niagara；电元素 → 范围感电区域。`EWorldElementType::Water` 已存在，走既有管线，无新架构。
- **浮力**：`BuoyancyComponent`（Buoyancy 插件）挂到 `PhysicsInteractable` 对象（木箱等），入水后浮起，受水面高度场影响微起伏。
- **湿身（远期）**：出水后角色材质参数混合，不做环境水渍系统。

## 8. 风险与规避

| 风险 | 表现 | 规避 |
|------|------|------|
| Water Advanced 是 Experimental，API 可能变 | 引擎升级后接口或 Niagara 资产路径变化 | 固定 UE 5.8，专项 PIE 验证子系统、Grid2D、Data Channel 和交互路由；保留自制 RT 兼容后端 |
| SLW 下 Lumen 反射强制镜面 | 想要粗糙反射做不到 | 鸣潮本就是镜面感，接受；确需粗糙再换 Translucent 路线 |
| 全局浅水窗口无法同时覆盖远距离湖面 | 远离玩家的 Lake 不保留实时细波 | 单人 Demo 只模拟最相关玩家周边 24m；远湖回到静态材质表现 |
| 涟漪"持续沸腾" | 行走触发频率过高 | WalkRippleInterval 下限 + 强度阈值过滤（静止不触发） |
| WaterBody 挖 Landscape 污染主图 | 测试地图被自动改地形 | 测试地图单独建，不用 ThirdPerson 主图 |

## 9. P0 实际落地状态（2026-08-10）

### 9.1 运行时结构

- 全局唯一 `UBasicShallowWaterSubsystem` 运行 `/WaterAdvanced/Niagara/Systems/Grid2D_SW_WaterBody`，通过 `/WaterAdvanced/Niagara/DataChannels/NDC_ShallowWater` 消费碰撞；两个 Lake 不各自创建模拟 RT。
- `AWorldWaterRippleRegion` 一湖一个，只负责空间过滤、标准交互语义转换和 `RegisterImpact(Position, Velocity, Radius)` 转发，不改 Lake Transform、Spline 或基础材质。
- Advanced 模式下 Region 不运行自制波动方程、不创建 `RG16F` RT；`SetWaterBodyMIDParameters` 只把官方 Normal/Velocity RT 接到 WaterBody 的运行时 MID。
- 角色涉水采用两层输入：移动/跑步由 WaterAdvanced 读取 SkeletalMesh Physics Asset 形成连续身体碰撞；跳跃/落地在该连续碰撞之外补充标准化一次性冲击；攻击/爆炸使用 `RegisterImpact` 注入明确的方向、速度与半径。三类输入最终进入同一浅水 Data Channel，但不能只用攻击链路是否成功来判断移动链路是否有效。
- `WaterBodyCollision` 对 Pawn / PhysicsBody / Destructible 保持 Overlap，对 `WorldDynamic` 设为 Block，满足 WaterAdvanced `RegisterImpact` 内部的阻挡检测。
- `UWorldWaterRippleConfig` 统一保存各来源半径映射、限频以及 Advanced 速度映射；引擎级网格预算放在 `DefaultEngine.ini`。

### 9.2 资产与地图

| 用途 | 资产 |
|------|------|
| 调参资产 | `/Game/PhysicsWorldDemo/Water/Config/DA_WorldWaterRippleConfig` |
| 主 Demo 地图 | `/Game/PhysicsWorldDemo/Maps/L_PhysicsWorldDemo_Lumen` |
| 角色浅水碰撞资产 | `/Game/Rover/Character/PHYS_Rover_Male`（14 个主要身体碰撞体） |
| 官方浅水 Niagara | `/WaterAdvanced/Niagara/Systems/Grid2D_SW_WaterBody` |
| 官方浅水 Data Channel | `/WaterAdvanced/Niagara/DataChannels/NDC_ShallowWater` |
| 兼容后端测试地图 | `/Game/PhysicsWorldDemo/Water/Maps/L_WaterP0` |

主地图两个 Region 的 `TargetWaterBody` 分别绑定 `WaterBodyLake` / `WaterBodyLake2`，并开启 `bUseWaterAdvancedShallowWater`。Region 根据目标 WaterBody Bounds 做粗过滤，再用与插件相同的 `ECC_WorldDynamic` 水面检测确认事件确实落在目标 Lake 内；矩形 Bounds 的空角和另一个 Lake 不会误计入。

### 9.3 当前调参入口

- 浅水窗口：`DefaultEngine.ini` 的 `ShallowWaterSimParameters.WorldGridSize`（当前 2400cm）和 `ResolutionMaxAxis`（当前 512）。
- 活跃预算：`MaxActivePawnNum`、`MaxImpulseForceNum`、`r.ShallowWater.FadeOutWait`（当前 15s）。
- 交互力度：DataAsset 的 `AdvancedMovementVelocityScale`、`AdvancedLandingVelocityScale`、`AdvancedAttackVelocityScale`、`AdvancedExplosionImpactSpeed`。
- 连续移动碰撞体积：`PHYS_Rover_Male` 中的胶囊尺寸；只有移动/跑步仍偏弱且确认 Collider 工作后再调该资产，避免用攻击的 `AdvancedAttackVelocityScale` 代偿。
- 安全范围：`AdvancedMinimumImpactSpeed`、`AdvancedMaximumImpactSpeed`，以及各来源 `RadiusScale` / 全局最小最大半径。
- 兼容 RT 后端：`WaveSpeed`、`DampingPerSecond`、`EdgeDampingWidth` 等参数只在 `bUseWaterAdvancedShallowWater=false` 时生效。

### 9.4 已验证证据

- `BuildEditor.ps1`：通过。
- 双 Lake 资产校验：1 WaterZone、2 WaterBodyLake、2 Advanced Region，绑定关系、样条完整性、Rover Physics Asset 绑定与 Body 数量全部通过。
- 双 Lake 专项 PIE：`UBasicShallowWaterSubsystem`、Grid2D 2400/512、0 个旧 Region RT；Rover Mesh 运行时带 `RigidMesh_ShallowWaterCollider`，Physics Asset 为 14 Bodies；Movement / Jump / Attack / Landing / Explosion 各 2 次，跨 Region 0 次，全部通过。最终 `total_forwarded=[6,5]`，额外一次来自角色真实移动事件。
- `ValidateRoverPIE.ps1`：本轮两次均停在既有 ground jump 位移阈值（0.25s 上升约 19cm），未改用户已调好的跳跃参数；该项不归因于 WaterAdvanced。
- 视觉水波幅度和材质观感留给有渲染 PIE 人工验收。

### 9.5 P0 边界

当前完成的是“统一交互请求 → WaterAdvanced 浅水 Data Channel → Grid2D 速度/法线场 → 现有双 Lake 材质”的单人局部模拟闭环。它不宣称两个相距较远的湖面可同时保留独立实时波场；游泳状态、浮力、湿身、元素反应和大范围 World Partition 水域仍属于 P1/P2。

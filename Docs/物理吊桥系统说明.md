# 物理吊桥交互设计说明

> 当前状态：结构方案完成，交互手感调优中
> 更新日期：2026-08-07
> 体验定位：开放区域中的动态通行节点，而不是独立的物理摆件

## 1. 玩家体验承诺

玩家不需要学习新操作，只通过站立、行走、奔跑、起跳、落地和攻击，就能从桥面的下沉、摆动与余振中读出自身行为强度。

设计优先级固定为：

1. **可稳定通行**：木板不能穿透、散架或把角色弹飞；
2. **反馈可读**：跑步应强于行走，落地应成为主要垂直冲击；
3. **恢复自然**：玩家离开后回到有弧度的静止状态，而不是停在歪斜姿势；
4. **输入不串扰**：普通攻击不应比跳跃和落地更强烈地扰动桥面；
5. **表现可扩展**：当前 Box / Cylinder 只验证规则，绳索、护栏、材质和声音后续替换。

当前体验判断：双侧约束和离桥恢复已达到结构目标；“攻击扰动大于落地反馈”仍未达到设计目标，因此不能把吊桥整体标记为体验验收完成。

## 2. 当前可玩结构

- `60` 块独立模拟刚体木板；
- 单板 `400 x 25 x 6cm`，桥面约 `16.77m x 4.00m`；

## 3. 为什么从中轴约束改为双侧约束

宽木板只在中轴设置一个关节时，刚体依然围绕质心求解，但左右边缘没有独立受力点。角色踩偏、碰撞或长链误差会形成较大的横向力臂，桥面容易呈现麻花状滚转。

当前每道板缝改为两条约束线：

| 约束线 | Linear | Angular | 设计职责 |
|---|---|---|---|
| 主约束（Negative Y） | X/Y/Z Locked | Swing1 Limited；其余 Free | 保持链长并允许沿桥方向俯仰 |
| 稳定约束（Positive Y） | X/Y Locked；Z Free | 全部 Free | 用第二个受力点抑制横滚，同时释放冗余自由度 |

两侧挂点位于 `Y = +/-(Plank Width / 2 - Anchor Lateral Inset)`。当前木板宽 `400cm`、内缩 `15cm`，因此位置为 `Y=+/-185cm`。

副约束不能再使用第二套完整锁定，否则两个关节会争夺同一刚体姿态，形成过约束抖动。双侧模式开启后，`Swing2 Limit` 和 `Twist Limit` 不再直接承担板缝横滚控制；真正起作用的是两个挂点形成的几何力臂。

## 4. 行为反馈规则

| 玩家行为 | 环境规则 | 当前状态 |
|---|---|---|
| 站立 | 使用约 `100kg` 角色质量形成持续承重，不循环注入脚步冲量 | 已接入 |
| 行走 | 按水平速度周期施加较弱向下冲量 | 已接入 |
| 奔跑 | 使用同一速度曲线，冲量明显高于行走 | 已接入 |
| 起跳 | `JumpCurrentCount` 确认真正起跳后，把离板动量传回桥面 | 已接入，表现仍需增强 |
| 落地 | 保留空中最大下落速度，避免落地帧速度被清零 | 已接入 |
| 攻击 | 动态基底上的攻击推进和原生 Push Force 归零，持续承重保持不变 | 已接入，仍有异常峰值 |
| 离开 | 延迟后渐入恢复力，回到自然弧线并进入 Chaos Sleep | 已接入 |

起跳与落地冲量分摊给脚下木板及前后相邻板，权重为 `0.6 / 0.2 / 0.2`。这样能扩大可见受力范围，并减少单块木板的尖峰和侧向翻滚。

攻击期间使用三项互相独立的规则：

- `AttackAdvanceScaleOnSimulatedBase = 0`：不让攻击位移推进桥面；
- `AttackPhysicsPushScaleOnSimulatedBase = 0`：关闭 CharacterMovement 的原生推力；
- `AttackStandingDownwardForceScaleOnSimulatedBase = 1`：保持持续承重，避免攻击开始时突然卸载并回弹。

## 6. 策划调参入口

单独调一座桥：选中 `BP_RopeBridge`，开启 `Rope Bridge -> Config -> Override Shared Settings`，修改 `Override Settings`。共享默认值位于 `DA_WorldInteractionConfig -> Settings -> Rope Bridge`。

按玩家感受调节：

| 想改变的感受 | 优先调节 | 注意事项 |
|---|---|---|
| 桥更有弧度 | `Bridge Sag` | 增大后要复查桥墩高度、端板角度和角色通行 |
| 行走更明显 | `Movement Impulse At Reference Speed` | 不要用提高频率代替强度，否则容易持续抖动 |
| 跑步与行走差异更大 | 提高参考冲量或拉开速度映射 | 用实际桥体速度比较，不只看输入冲量 |
| 起跳蹬板更明显 | `Minimum/Maximum Jump Takeoff Impulse` | 当前最小值过高会让不同速度的起跳趋于固定反馈 |
| 落地更有重量 | `Landing Impulse Scale` 和上下限 | 必须同时验证落地实际峰值高于攻击峰值 |
| 离开后更快回正 | 恢复 Stiffness / Damping | 恢复只能在无人接触后启动，避免与玩家争夺桥面 |
| 中段减少横滚 | 扩大双侧挂点间距或提高 Solver | 不要重新叠加第二套完整角度锁定 |
| 板缝减少拉开 | Position Iterations / Linear Projection | 先提高求解精度，再小幅增加 Projection |

## 8. 当前遗留问题

### 攻击扰动大于落地

Attack01 的桥体速度峰值发生在 Recovery 约 `0.83s`，而不是武器 Active 命中窗口。当前已经排除：

- 武器直接碰撞桥板；
- `UWorldInteractionSubsystem` 环境交互请求；
- 攻击推进 Root Motion Source；
- 动画 Root Motion；
- CharacterMovement Push Force；
- 角色相对脚下木板的主动位移。

角色攻击时相对木板位移为 `0cm`，但世界位移约 `46.7cm`，说明角色是被桥面带动。下一步要围绕 Recovery 状态切换、Movement Base 更新和持续承重的帧级变化继续定位，并增加明确失败阈值。

### 跳跃反馈仍不够突出

当前起跳和落地的最小值与最大值实际收敛到 `800 / 2200`，过阈值后接近固定冲量，速度差异不够丰富。后续需要先让检测和实际桥体响应正确，再重新打开速度映射范围，避免只靠继续加大数值制造晃动。

### 规模与美术尚未验证

- 当前没有多座 60 板桥同时运行的性能预算；
- 火球或爆炸作用于吊桥的稳定性尚未纳入专项测试；
- 目前没有绳索、护栏、最终材质和声音，只能作为机制原型展示。

## 9. 验收出口

吊桥进入“体验完成”前必须满足：

1. 攻击峰值不高于落地峰值，并接近同等时长的站立对照；
2. 走、跑、起跳、落地使用同一套桥体响应指标形成可读层级；
3. 角色可持续通过，不出现塌桥、穿透、弹飞或镜头不可控；
4. 离桥后 10 秒内恢复自然弧线并休眠；
5. 双侧板缝、端点和长链误差均通过无头 PIE；
6. 增加多桥与爆炸压力测试后，再讨论开放区域规模化使用。

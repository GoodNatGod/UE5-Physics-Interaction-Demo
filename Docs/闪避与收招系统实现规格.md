# 闪避与收招系统 - UE5.8 Codex 实现规格

> **用途**：作为 Codex / UE5 实现输入，约束攻击收招、统一 Sprint/Dodge 输入、战斗闪避和完美闪避的实现。  
> **工程**：`RoverReplica`，Windows 单机，C++ 核心逻辑 + AnimBP 表现。  
> **前置依赖**：`URoverLocomotionComponent`、`URoverAnimInstance`、攻击/受击资源导入管线。  
> **版本**：0.2.3 - ComboWindow 与闪避取消规则修订版。  
> **执行顺序**：先完成攻击、敌人受击和收招，闪避最后实现。

---

## 0. 本版结论

本系统可以实现，但必须遵守当前工程的责任边界：

- `URoverLocomotionComponent` 是角色位移、输入锁、MoveStop、GroundTurn 和特殊移动的唯一权威。
- `URoverCombatComponent` 管理攻击阶段、连招、伤害、受击、无敌和完美闪避，不直接写入 `CharacterMovement`。
- `ARoverCharacter` 持有两个组件，并负责在组件之间转发请求、确认和结束事件。
- `URoverAnimInstance` 只镜像组件状态并转发 AnimNotify，不拥有游戏规则。
- 攻击、闪避和受击是全身动作；只有明确验证过的收招尾段允许逐步释放下半身给 Locomotion。
- 不提供会无条件清除其他状态的 `LockInput()` / `UnlockInput()`。所有特殊动作必须通过状态或带 `RequestId` 的请求确认机制管理。

本版删除以下旧方案：

- 删除 `UPROPERTY FRoverMovementSettings*`。
- 删除 `CombatComponent` 直接设置 `Velocity` 或调用 `AddInputVector`。
- 删除 Montage 完全结束后才开始播放收招的逻辑。
- 删除将 Dodge 放在 Spine 以上 Layered Blend 分支中的结构。
- 删除按键释放时重新判断战斗上下文的做法。

## 1. 范围与实施顺序

### 1.1 本文覆盖

1. 攻击动画内的真实收招阶段。
2. 收招期间恢复移动、缓存新攻击和允许高优先级取消。
3. `IA_Sprint` 向统一 `IA_Dodge` 输入的迁移。
4. 战斗闪避的全身动画、碰撞安全位移和无敌帧。
5. 完美闪避、时缓和反击窗口。

### 1.2 实施顺序

| 阶段 | 内容 | 依赖 | 完成信号 |
|---|---|---|---|
| P0-A | Attack01 单次攻击 + 第二个漂泊者敌人 + 轻受击 | 攻击/受击资源 | 攻击命中一次，敌人正确受击 |
| P0-B | Attack01~03 连招 + Montage Notify | P0-A | AAA 稳定，输入缓存不丢失 |
| P0-C | 收招尾段 + 移动恢复 | P0-B | 停止连击会完整收招，持续移动无卡顿 |
| P1 | 重受击、击退、死亡、Hit Stop、相机反馈 | P0-C | 玩家能感知命中重量 |
| P2-A | 统一 Sprint/Dodge 输入 + 地面闪避 | P1 | 非战斗冲刺、战斗闪避互不串状态 |
| P2-B | 无敌帧 + 完美闪避 + 反击窗口 | P2-A + 敌人攻击 | 实际攻击穿过无敌帧时触发一次完美闪避 |
| P3 | 四方向闪避、空中闪避、连续闪避限制 | P2-B + 选定动画 | 方向和次数规则稳定 |

闪避不得提前到攻击和受击闭环之前。没有敌人攻击判定时，完美闪避无法得到有效验证。

## 2. 已确认的资源条件

### 2.1 攻击与受击

当前素材库已确认存在：

- 地面攻击：`Attack01~05`、`Attack07`、`Attack09` 及 `AM_` 版本。
- 空中攻击：`AirAttack_Start`、`AirAttack_Loop`、`AirAttack_End`。
- 轻受击：`Behit_S_L`、`Behit_S_R`。
- 重受击：`Behit_B_L`、`Behit_B_R`。
- 击退：`Behit_Push_Start/Loop/Fall`。
- 击飞：`Behit_Fly_Start/Loop/Fall`。
- 死亡：`Death`。

地面攻击没有独立命名的 `Attack_End`。不得假设缺少收招，必须先完整预览 `Attack01~03`，确认收刀动作是否已经包含在每个攻击片段的尾部。

### 2.2 武器

正式武器已锁定为：

```text
D:\BaiduNetdiskDownload\艾斯3d建模-鸣潮 通用类型武器-附赠品\刀剑类型-01\R2Sword001.fbx
```

同目录还包含 `R2Sword001.max`，以及 `TEX` 目录中的 `T_R2Sword001Md20001_D.png` 和 `T_R2Sword001Md20001_N.png`。实现使用 FBX，不要求 UE 读取 `.max`。

该 FBX 是 Binary v7400（3ds Max 导出）的蒙皮骨骼武器，不是 Static Mesh：

```text
Sword_Bone01
  |-- Sword_Bone02
  |     `-- Sword_Bone03
  |           `-- R2Sword001Md20001_LOD0
  `-- Scabbard_Bone001
        `-- R2Scabbard001Md20001_LOD0
```

| 项目 | 已确认内容 | 实现结论 |
|---|---|---|
| 骨骼 | 4 根，刀身与刀鞘均有蒙皮权重 | 导入为 Skeletal Mesh |
| 刀身 | `R2Sword001Md20001_LOD0` | 攻击时显示 |
| 刀鞘 | `R2Scabbard001Md20001_LOD0`，独立骨骼分支 | 当前版本默认隐藏 |
| 材质 | 单材质槽，源名称 `MI_R2Sword001Md20001` | 使用 D/N 贴图重建项目材质实例 |
| 贴图 | `T_R2Sword001Md20001_D.png`、`T_R2Sword001Md20001_N.png` | Base Color 与 Normal |
| 源命名 | `\Aki\Character\Weapon\Sword\R2Sword001\` | 仅记录资产来源命名，不作为运行时路径 |

P0-A 使用以下目标资产结构：

- `SK_R2Sword001`：武器 Skeletal Mesh。
- `SKEL_R2Sword001`：武器自己的 Skeleton，不指定或合并到 Rover Skeleton。
- `MI_R2Sword001`：项目内材质实例。
- 不需要武器 Physics Asset；如果导入器自动生成，正式角色配置也不得启用其碰撞或物理模拟。
- FBX 没有供角色播放的动画时关闭 Import Animations。

导入后校验单位比例、前向轴、握柄 Pivot、蒙皮、材质和法线方向。若原始 Pivot 不适合直接握持，优先通过右手 Socket Transform 校正；只有多个角色共用时仍无法稳定对齐，才修改源模型 Pivot。

在 `SKEL_R2Sword001` 上创建 `WeaponTraceBase` / `WeaponTraceTip` Socket，分别校准到有效刀刃根部和尖端。攻击 Trace 每帧读取这两个 Socket 的世界位置；不要用角色胶囊中心推算刀刃。显示模型和伤害检测保持解耦，后续替换武器外观时只需提供同语义 Socket，不重写伤害逻辑。

正式武器采用“常驻挂载、按攻击显隐”，不在每次攻击时 Spawn/Destroy：

- `USkeletalMeshComponent` 从角色初始化开始就挂在右手 Socket，默认 `SetVisibility(false)`。
- 初始化时隐藏 `Scabbard_Bone001` 分支；整件组件显示后只出现刀身。若导入结果无法按骨骼可靠隐藏刀鞘，则拆分刀身/刀鞘 Skeletal Mesh，而不是依赖共享材质槽透明度。
- 首段攻击动画确认进入时显示；连招切段、ComboWindow 和 Recovery 期间持续显示。
- 当前攻击链正常结束、被受击/闪避/死亡中断、Montage 异常结束或角色 EndPlay 时隐藏。
- 攀爬、滑翔、钩锁、冲刺、普通移动和其他探索状态下保持隐藏。
- 显隐只控制渲染。武器碰撞默认关闭，伤害仍由 `RoverAttackActiveBegin/End` 独立启停轨迹检测。
- `WeaponTraceBase` / `WeaponTraceTip` 始终跟随武器骨骼；武器不可见时不得运行攻击 Trace。

这样探索动画无需适配武器骨骼，武器出现的首帧同时构成明确的攻击开始信号。

### 2.3 闪避

素材库没有明确命名的 `Dodge_F/B/L/R`。候选动作：

- `Jump_Faith_Roll`

## 3. 系统架构

### 3.1 组件职责

#### `URoverCombatComponent`

负责：

- 攻击请求、连招索引和输入缓存。
- Attack Phase 与 Recovery Phase。
- 攻击命中去重、伤害和韧性。
- 受击、无敌、完美闪避和反击窗口。
- Dodge 意图和 `DodgeRequestId`。

不负责：

- 直接写入 `CharacterMovement->Velocity`。
- 直接取消 MoveStop/GroundTurn。
- 直接持有或调用 `URoverLocomotionComponent`。

#### `URoverLocomotionComponent`

负责：

- 接受或拒绝特殊移动请求。
- 闪避方向、距离、持续时间和碰撞安全位移。
- 闪避期间的移动输入屏蔽。
- 与 GroundTurn、MoveStop、Landing 和 Airborne 的优先级处理。
- 特殊移动 watchdog 和退出后的速度恢复。

#### `ARoverCharacter`

负责：

- 输入路由。
- 将 Combat 的 Dodge 意图转发给 Locomotion。
- 将 Locomotion 的接受、进入、退出结果转发回 Combat。
- 转发攻击、受击和动画 Notify 事件。

组件之间不直接互相引用。

#### `URoverAnimInstance`

负责：

- 镜像 Combat/Locomotion 状态到 AnimBP。
- 播放正确的 Montage/State。
- 将 AnimNotify 转发到 Character，再由 Character 转发到组件。

不在 AnimInstance 中计算伤害、决定是否能闪避或推进连招。

### 3.2 请求确认机制

闪避沿用 GroundTurn/MoveStop 的请求确认模式：

```text
CombatComponent 生成 DodgeRequestId 和 DodgeIntent
    -> Character 转发给 LocomotionComponent
    -> Locomotion 检查当前移动状态
    -> Accepted / Rejected 回传 Character
    -> Character 回传 CombatComponent
    -> AnimInstance 观察 RequestId 并进入全身 Dodge
    -> AnimNotify 确认 DodgeEntered / DodgeExited
    -> watchdog 在动画丢失时兜底退出
```

所有 Complete/Cancel 操作必须携带 `RequestId` 且可重复调用，不得让旧 Notify 结束新的闪避。

## 4. 统一 Sprint/Dodge 输入

### 4.1 行为

| 输入时上下文 | 按下 | 持续按住 | 松开 |
|---|---|---|---|
| 非战斗 | 开启现有 Sprint | 保持 Sprint | 关闭 Sprint |
| 战斗 | 请求一次 Dodge | 不重复请求 | 不改变 Dodge 状态 |

上下文只在按下瞬间判定。本次按键的释放必须按照按下时保存的路由处理，不能重新判断上下文。

### 4.2 按键映射

- 键盘：`Left Shift` + `Right Mouse Button` -> `IA_Dodge`。
- 手柄：`Gamepad Face Button Right (B)` -> `IA_Dodge`。
- 当前 B 同时绑定了 Crouch，迁移时必须从 Crouch 映射中移除 B。
- P2 阶段 Crouch 暂时只保留键盘 `C`，后续再确认手柄替代键。
- 旧 `IA_Sprint` 在迁移期可以保留资源，但不能和 `IA_Dodge` 同时映射 Shift。

右键未来若用于锁定或瞄准，必须通过 Mapping Context 优先级重新规划，不能让两个 Action 同时触发。

### 4.3 稳定的按下/释放路由

```cpp
UENUM()
enum class ERoverDodgeInputRoute : uint8
{
    None,
    Sprint,
    CombatDodge,
};

ERoverDodgeInputRoute ActiveDodgeInputRoute = ERoverDodgeInputRoute::None;

void ARoverCharacter::HandleDodgeStarted()
{
    ActiveDodgeInputRoute = ERoverDodgeInputRoute::None;

    if (CombatComponent && CombatComponent->IsInCombatContext())
    {
        ActiveDodgeInputRoute = ERoverDodgeInputRoute::CombatDodge;
        CombatComponent->RequestDodgeIntent();
        return;
    }

    ActiveDodgeInputRoute = ERoverDodgeInputRoute::Sprint;
    LocomotionComponent->SetSprintHeld(true);
}

void ARoverCharacter::HandleDodgeReleased()
{
    if (ActiveDodgeInputRoute == ERoverDodgeInputRoute::Sprint)
    {
        LocomotionComponent->SetSprintHeld(false);
    }
    ActiveDodgeInputRoute = ERoverDodgeInputRoute::None;
}
```

`Completed` 和 `Canceled` 都绑定 `HandleDodgeReleased()`。失去焦点、切换 Mapping Context 和角色 EndPlay 时也必须清除 SprintHeld。

### 4.4 战斗上下文

```cpp
bool URoverCombatComponent::IsInCombatContext() const
{
    return CombatPhase != ERoverCombatPhase::None ||
        LockedTarget.IsValid() ||
        IsInHitReaction() ||
        HasRecentCombatEvent();
}
```

`HasRecentCombatEvent()` 使用有效的 `LastCombatEventWorldTime`，初始值必须表示“从未进入战斗”，不能用初始为 0 的累计计时器导致开局数秒误判。

P2 不启用“附近存在敌人就自动进入战斗”。该规则会让悬崖探索中的 Shift 行为不可预测。

## 5. 攻击与收招

### 5.1 Fun Hypothesis

> 玩家停止连击时，角色必须完成当前攻击对应的收刀/归位动作；玩家持续移动时，下半身应尽早恢复控制，不能先跳到 Idle 再开始走。

### 5.2 Attack Phase

```cpp
UENUM(BlueprintType)
enum class ERoverCombatPhase : uint8
{
    None,
    Startup,
    Active,
    ComboWindow,
    Recovery,
};
```

每个攻击 Montage 至少包含以下 Notify，并包含一个真正的 `ComboWindow` AnimNotifyState：

| Notify | 作用 |
|---|---|
| `RoverAttackStarted` | 确认攻击动画已经进入 |
| `RoverAttackActiveBegin` | 开启武器轨迹检测 |
| `RoverAttackActiveEnd` | 关闭轨迹检测 |
| `ComboWindow` AnimNotifyState | 默认从该段 50% 开始并延伸到 Montage 末尾；窗口内输入立即切下一段 |
| `RoverRecoveryBegin` | 进入真实收招尾段，按配置恢复移动 |
| `RoverAttackFinished` | 正常结束并清理当前攻击 |

顺序必须满足：

```text
Started < ActiveBegin < ActiveEnd <= ComboWindowBegin < RecoveryBegin < Finished <= ComboWindowEnd
```

`ComboWindowBegin=0.50` 是 `[PLACEHOLDER]`，必须保存在每段 AttackDefinition 中，允许逐段微调；`ComboWindowEnd` 固定为 Montage 末尾，因此窗口与 Recovery 可以重叠。

`RoverAttackStarted` 确认首段攻击后调用 `SetCombatWeaponVisible(true)`。后续连招段不得先隐藏再显示，避免切段闪烁；只有整个攻击链结束或被中断时才调用 `SetCombatWeaponVisible(false)`。

### 5.3 收招不是 Montage 结束后的额外计时器

`Recovery` 是攻击动画本身的尾段，从 `RoverRecoveryBegin` 到 `RoverAttackFinished`。

- `OnMontageEnded` 不启动 Recovery。
- 正常路径由 `RoverAttackFinished` 清理状态。
- `OnMontageEnded` 只处理异常中断或缺失 Notify 的兜底清理。
- Recovery 的实际时长来自动画 Notify，不使用统一硬编码 `0.2s` 覆盖所有攻击。

如果完整预览后确认某个 Attack FBX 确实没有收招尾段，才允许：

1. 从同骨架素材中选择对应 Recovery 动画；或
2. 通过 Animation Sequence 截取/拼接生成 Recovery；或
3. 将该攻击标记为资源不完整，不能进入正式 AAA 链。

禁止用静态 Pose 淡出冒充明确要求的收刀动作。

### 5.4 Recovery 输入规则

| Recovery 中输入 | 结果 |
|---|---|
| Walk/Run | 在 `RoverRecoveryBegin` 后恢复物理移动 |
| Jump | 按 AttackDefinition 的 `bCanJumpCancelRecovery` 决定 |
| Attack | `ComboWindow` 仍开启时立即进入下一段；Montage 已结束时按 0.55s 续段计时决定是否继续 |
| Dodge | 立即取消攻击、重置连击，再请求闪避 |
| Skill | 留给后续技能系统的数据规则 |

ComboWindow 内按 Attack 必须立即中断当前段并播放下一段。窗口开启前按 Attack 则进入 `0.25s` 输入缓冲；窗口开启时只消费仍有效的缓冲。Montage 完全结束后启动 `0.55s` 续段计时，计时内输入继续下一段，超时后将 `CurrentComboIndex` 重置为 `-1`。

### 5.5 移动恢复

`RoverRecoveryBegin` 由 Character 转发到 Locomotion，释放的只能是“当前攻击请求持有的移动限制”。不得调用无条件 `UnlockInput()`，否则会覆盖 Landing、GroundTurn、MoveStop 或后续特殊动作的限制。

推荐使用拥有者/请求 ID：

```cpp
void BeginCombatMovementRestriction(int32 AttackRequestId);
void EndCombatMovementRestriction(int32 AttackRequestId);
```

旧攻击的 Notify 无权结束新攻击的限制。

### 5.6 Montage 结束兜底

```cpp
void URoverCombatComponent::HandleAttackMontageEnded(
    int32 RequestId,
    bool bInterrupted)
{
    if (RequestId != ActiveAttackRequestId)
    {
        return;
    }

    DisableWeaponTrace();
    if (!bReceivedAttackFinishedNotify || bInterrupted)
    {
        SetCombatWeaponVisible(false);
        CancelAttackState(RequestId);
    }
}
```

正常收到 `RoverAttackFinished` 时，也必须在清理攻击状态前隐藏武器。watchdog 应覆盖 Montage 未播放、Notify 丢失和错误资产，并兜底关闭 Trace、隐藏武器，但正常收招节奏不能由 watchdog 决定。

## 6. AnimGraph 结构

### 6.1 原则

- Attack、Dodge、HitReaction 默认是全身动作。
- Recovery 是否释放下半身取决于素材审查结果和 AttackDefinition。
- AnimInstance 镜像状态，不用 `FInterpTo` 猜测游戏阶段。
- 动作退出使用 Montage Blend Out、Inertialization 和动画曲线，不用额外 Idle 过渡帧。

### 6.2 推荐图结构

```text
Locomotion StateMachine
    -> Save Cached Pose "LocomotionPose"

LocomotionPose
    -> Slot "FullBodyCombat"
    -> Save Cached Pose "CombatSlotPose"

Layered Blend Per Bone
    Base  = LocomotionPose
    Blend = CombatSlotPose
    Bone  = 经骨架确认后的 Spine 起点
    -> "UpperBodyRecoveryPose"

Blend Poses
    A = CombatSlotPose            // Startup / Active / Dodge / HitReaction
    B = UpperBodyRecoveryPose     // 仅允许下半身释放的 Recovery
    Alpha = RecoveryLowerBodyReleaseAlpha

    -> Inertialization
    -> Output Pose
```

规则：

- `RecoveryLowerBodyReleaseAlpha = 0`：保持全身 Combat Pose。
- 进入允许释放下半身的 Recovery 后，使用 Montage Curve 在明确时长内从 0 过渡到 1。
- Dodge 和 HitReaction 始终强制 Alpha 为 0，绝不能只播放上半身。
- 如果攻击包含必须保留的腿部动作或 Root Motion，该攻击的 Recovery 也保持 Alpha 为 0。

### 6.3 AnimInstance 镜像变量

```cpp
UPROPERTY(BlueprintReadOnly, Transient, Category = "Rover|Combat")
ERoverCombatPhase CombatPhase = ERoverCombatPhase::None;

UPROPERTY(BlueprintReadOnly, Transient, Category = "Rover|Combat")
bool bIsDodging = false;

UPROPERTY(BlueprintReadOnly, Transient, Category = "Rover|Combat")
bool bInHitReaction = false;

UPROPERTY(BlueprintReadOnly, Transient, Category = "Rover|Combat")
int32 CurrentComboIndex = 0;

UPROPERTY(BlueprintReadOnly, Transient, Category = "Rover|Combat")
float RecoveryLowerBodyReleaseAlpha = 0.0f;
```

`RecoveryLowerBodyReleaseAlpha` 来自动画曲线或 CombatComponent 的确定性归一化时间。不要使用“Recovering 时目标仍为 1”的通用 CombatLayerBlendWeight。

## 7. 战斗闪避

### 7.1 触发优先级

闪避是高优先级动作，但不是无条件取消：

1. `CanRequestDodge()` 先检查当前攻击是否处于允许取消窗口。
2. 不可取消时直接拒绝，不播放 Montage，也不生成位移请求。
3. 可取消时先以 RequestId 取消攻击，再请求闪避。
4. Recovery 可被闪避取消。
5. MoveStop 和普通 GroundTurn 可由 Locomotion 安全取消后进入闪避。
6. Heavy/Roll Landing、击飞、倒地和不可中断特殊动作拒绝闪避。

旧方案中“超过攻击前 30% 不调用 CancelAttack，但仍播放 Dodge Montage”的行为禁止出现；同 Slot 覆盖也属于取消，必须受同一规则约束。

### 7.2 闪避方向

按下瞬间快照方向：

- 有移动输入：相机相对输入方向。
- 无移动输入且有锁定目标：优先角色后方，后续可扩展侧闪选择。
- 无移动输入且无锁定目标：角色后方。
- 闪避期间不实时跟随摇杆改变方向。

方向由 Character 计算后放入 `FRoverDodgeIntent`，Locomotion 再标准化为水平单位向量。

### 7.3 位移权威

优先级：

1. 如果选定 Dodge 动画具有经过验证的 Root Motion，则使用 Animation Root Motion。
2. 如果动画原地播放，则由 Locomotion 使用 `FRootMotionSource_MoveToForce` 或等价的 CharacterMovement Root Motion Source 驱动胶囊。
3. 两种方式只能启用一种，禁止动画 Root Motion 与 C++ 位移叠加。

Root Motion Source 的目标位置、时长和优先级由 Locomotion 设置，移动仍经过 CharacterMovement 的地面和碰撞处理。禁止 CombatComponent 每帧 `AddInputVector(DeltaMove / DeltaTime)`，该 API 接收的不是世界位移。

闪避被墙阻挡时允许实际距离缩短，不允许穿墙、瞬移到墙后或持续顶墙累积位移。

### 7.4 闪避阶段

```cpp
UENUM(BlueprintType)
enum class ERoverDodgePhase : uint8
{
    None,
    Startup,
    Invincible,
    Recovery,
};
```

阶段优先由动画 Notify 驱动：

- `RoverDodgeEntered`
- `RoverDodgeInvincibleBegin`
- `RoverDodgeInvincibleEnd`
- `RoverDodgeRecoveryBegin`
- `RoverDodgeExited`

配置中的时间仅作为资产缺失 Notify 时的 watchdog，不是正常路径。

### 7.5 CanRequestDodge

```text
拒绝：
- 已经在 Dodge
- 当前攻击不在可取消窗口
- Heavy 或 Roll Landing
- HitReaction / Knockback / Launched / Downed
- 另一个不可中断 Special 动作
- 空中且本次滞空闪避次数已用完

允许但需要先取消：
- Attack 的可取消窗口
- Recovery
- MoveStop
- 普通 GroundTurn
```

P2-A 只实现地面闪避。空中闪避和每次滞空次数在 P3 实现，不在 P2-A 留半成品分支。

### 7.6 退出与恢复

Locomotion 完成闪避后：

- 清除对应 Dodge RequestId 的特殊移动。
- 恢复 CharacterMovement 被本次请求临时覆盖的参数。
- 如果移动键仍按住，下一帧直接进入 Walk/Run/Sprint，不经过 Idle。
- 不调用 `StopMovementImmediately()`。
- 保留碰撞阻挡后的合法速度，不制造一帧反向速度。

CombatComponent 收到退出事件后关闭无敌并结束 DodgePhase。动画 Notify 和 watchdog 重复到达时必须幂等。

## 8. 无敌帧与完美闪避

### 8.1 无敌不是关闭查询碰撞

玩家受击体必须继续能被敌人攻击 Trace 查询到，否则系统不知道攻击是否穿过了闪避。

伤害入口统一处理：

```text
Enemy Attack Trace 命中 Rover HitReceiver
    -> HitReceiver 将命中提交给 CombatComponent
    -> DodgePhase == Invincible：拒绝伤害并尝试触发 Perfect Dodge
    -> 其他状态：正常结算伤害和受击
```

一次闪避最多触发一次 Perfect Dodge，同一次敌人攻击也必须通过 AttackHitId 去重。

### 8.2 Perfect Dodge Sensor

如果需要比真实受击体更宽容的判定，创建独立 Query-Only Sensor：

- 只在无敌帧开启。
- 推荐初始缩放 `[PLACEHOLDER: 1.2~1.35]`。
- 不改变真实受击 Capsule。
- Sensor 命中只触发 Perfect Dodge，不触发伤害。

删除未使用的 `DodgePerfectWindow`。P0/P2 的定义统一为“敌人有效攻击在无敌帧内命中真实受击体或 Perfect Sensor”。

### 8.3 时缓

全局时缓由单独的时间效果所有者管理，至少满足：

- 保存并恢复进入效果前的 Time Dilation，而不是固定恢复为 1。
- 使用现实时间或不受当前 Time Dilation 影响的计时。
- 组件销毁、关卡结束和新时缓覆盖旧时缓时能安全恢复。
- 不在局部临时 `FTimerHandle` 的 lambda 中裸捕获可能销毁的 `this`。

P2-B 初始参数：

- `PerfectSlowTimeScale = [PLACEHOLDER: 0.3]`
- `PerfectSlowRealDuration = [PLACEHOLDER: 0.3s]`
- `PerfectDamageMultiplier = [PLACEHOLDER: 1.2]`
- `PerfectDamageDuration = [PLACEHOLDER: 3.0s]`

所有数值必须进入 CombatConfig 并通过 Playtest 调整。

### 8.4 反击窗口

完美闪避后开启 `[PLACEHOLDER: 0.8s]` 反击窗口：

- 窗口内按 Attack 进入配置指定的 DodgeCounterAttack。
- 不在代码中硬编码 `StartAttack(3)`。
- AttackDefinition 通过资产引用决定反击动作、伤害和取消规则。
- 反击窗口结束后恢复正常 Attack01 起手。

## 12. 自动化验证

### 12.1 资源验证

- Attack01~03 与 Rover Skeleton 一致。
- Montage Notify 顺序合法且每个必要 Notify 恰好存在一次。
- AttackDefinition 引用有效 Montage。
- Root Motion 策略与动画资产设置一致。
- `SK_R2Sword001` 使用独立武器 Skeleton 导入，刀身、刀鞘蒙皮和 D/N 贴图均正确。
- 武器 Skeletal Mesh 默认隐藏并正确挂载右手 Socket；`Scabbard_Bone001` 分支保持隐藏，显隐不改变攻击 Trace 配置。
- `WeaponTraceBase` / `WeaponTraceTip` 位于有效刀刃两端，挥砍过程中连续且不反向跳点。
- Dodge 资产确定后验证根骨位移、持续时间和方向。

### 12.2 Recovery PIE

场景：玩家面对第二个漂泊者敌人。

1. 单按 Attack01，不继续输入：必须经过 Active、ComboWindow、Recovery、Finished。
2. 在 ComboWindow 输入：同调用栈进入 Attack02，不播放 Attack01 的剩余部分。
3. ComboWindow 前输入：0.25s 内由窗口开启消费；超过 0.25s 后丢弃且不跳段。
4. 从攻击开始持续按 W：在 RecoveryBegin 后 `<=0.08s` 恢复有效位移。
5. Recovery 期间动画不得经过一帧 Idle/Stand 再切 Run。
6. Montage 人工中断：武器 Trace、移动限制和 Combo 状态全部清理。
7. 探索态武器不可见；AttackStarted 显示，连招切段不闪烁，完整 Recovery 结束后隐藏。
8. 受击、闪避、死亡、Montage 中断和 watchdog 退出后，武器必须隐藏且 Trace 关闭。
9. Montage 正常结束后 0.55s 内输入继续下一段；超时后 `CurrentComboIndex == -1`。
10. Startup、Active、ComboWindow、Recovery 任一阶段请求 Dodge，都必须立即中断攻击并重置连击。

### 12.3 输入路由 PIE

1. 非战斗按 Shift -> Sprint；松开前进入战斗上下文 -> 释放仍必须结束 Sprint。
2. 战斗按 Shift -> 只请求一次 Dodge；持续按住不得每帧重复 Dodge。
3. `Canceled`、失去焦点和 EndPlay 后 SprintHeld 为 false。
4. 手柄 B 不再触发 Crouch。

### 12.4 Dodge PIE

1. 空地闪避：距离和持续时间在配置容差内。
2. 墙前闪避：不穿墙、不瞬移，状态按时结束。
3. Root Motion 资产与 Root Motion Source 不得同时产生位移。
4. 攻击允许取消窗口：3 帧内进入 Dodge。
5. 攻击不可取消窗口：Dodge Request 被拒绝，攻击继续。
6. Recovery 中 Dodge：Recovery 清理并进入全身 Dodge。
7. 闪避结束持续按 W：不经过 Idle，快速恢复移动。
8. MoveStop、GroundTurn、Landing 和现有相机回归全部通过。

### 12.5 Perfect Dodge PIE

1. 敌人有效攻击在 Startup 命中：正常受伤。
2. 在 Invincible 命中：不受伤并触发一次 Perfect Dodge。
3. 在 Recovery 命中：正常受伤。
4. 多段 Trace 使用同一 AttackHitId：只触发一次。
5. 时缓按现实时间结束，恢复进入效果前的 Time Dilation。

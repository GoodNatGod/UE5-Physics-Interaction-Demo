# 漂泊者战斗系统设计文档 — UE5.8 实现规格

> **用途**：作为移动系统完成后的战斗层设计，与 `RoverLocomotionComponent` 并行构建  
> **参考**：鸣潮（Wuthering Waves）漂泊者战斗系统  
> **前置依赖**：地面移动系统（Idle/Walk/Run/Sprint）、跳跃/着地系统、AnimNotify 回调机制  
> **版本**：0.2.0 · P0 实现记录

---

## 0. Fun Hypothesis & Design Pillars

### Fun Hypothesis

> **玩家输入一个攻击键后，角色在 3 帧内开始播放攻击动画，且在任何攻击前摇阶段都可取消进入闪避——让攻防转换变成直觉而非规划。**

### Design Pillars（不可妥协的设计原则）

| # | Pillar | 含义 | 检验标准 |
|---|--------|------|---------|
| 1 | **3 帧响应** | 从输入到 AnimBP 进入攻击状态的延迟 ≤ 50ms（3 帧@60fps） | 高帧率录制逐帧分析 |
| 2 | **全程可取消** | 任何攻击动作前 30% 归一化时间内可被闪避/跳跃取消 | Playtest：按闪避键后 0.15s 内进入闪避动画 |
| 3 | **判定先于视觉** | 命中判定的 Trace 比视觉特效早 1 帧触发，确保玩家"看到打到的时候已经判了" | 对比 AnimNotify 时间戳与视觉特效时间戳 |
| 4 | **受击方向一致** | 受击动画的方向与伤害来源方向偏差 ≤ 15° | 自动测试：验证受击角色的 RootBone Yaw 偏差 |
| 5 | **战斗-移动零摩擦** | 战斗与移动系统使用同一套 Locomotion 状态机，不存在"进入战斗模式"的硬切换 | 战斗中随时可以冲刺/跳跃/攀爬 |

## 1. 架构决策：战斗系统如何嵌入现有移动系统

### 1.1 为什么不在 AnimBP 里加 Combat 状态机

现有 AnimBP 的 `RoverLocomotion` 状态机管理 11 个移动/跳跃/着陆状态。如果把战斗状态也塞进去，状态机将膨胀到 30+ 状态，转换边呈指数增长。

**决策**：战斗动画通过 **Layered Blend Per Bone** 叠加在移动动画之上，不进入主状态机。

```
AnimGraph 管线（修改后）：
  RoverLocomotion StateMachine（现有）
    → Layered Blend Per Bone（上半身：战斗动画，下半身：继续移动动画）
      → Foot IK
        → Motion Warping
          → Output Pose
```

**Rationale**：
- 鸣潮的战斗允许边移动边攻击（冲刺攻击、跳跃攻击、滑铲攻击），动画上半身播攻击、下半身继续移动
- 分层混合让战斗和移动完全解耦，各自独立调参
- 不需要在移动状态机里加 15+ 条 "某战斗状态 → 某移动状态" 的转换边

### 1.2 新增 C++ 组件

```
URoverCombatComponent : UActorComponent
  ├── 连招状态管理
  ├── 输入缓冲队列
  ├── 取消窗口判定
  ├── 命中判定调度
  └── 伤害计算
```

与 `URoverLocomotionComponent` 平级挂载在 `ARoverCharacter` 上。两个组件通过 `ARoverCharacter` 的事件转发通信，不直接互相引用。

### 1.3 新增 AnimNotify

```
AnimNotify_RoverAttackEnableHit     // 开启命中判定
AnimNotify_RoverAttackDisableHit    // 关闭命中判定
AnimNotify_RoverAttackComboWindow   // 连招窗口开启
AnimNotify_RoverAttackComboEnd      // 连招窗口关闭
AnimNotify_RoverAttackCancelWindow  // 可取消窗口结束
```

## 2. 连招系统

### 2.1 Fun Hypothesis（连招）

> **按下攻击键不放也能打完三连，但精确输入第三段的时机触发 Perfect Combo 获得额外伤害——同时满足休闲玩家和硬核玩家的需求。**

### 2.2 连招结构

```
轻攻击连段（Light Attack Combo）：
  Attack_L1 → Attack_L2 → Attack_L3
    │            │            │
    │ 摇杆前+攻   │ 摇杆前+攻   │ 摇杆前+攻
    ▼            ▼            ▼
  Attack_L1F   Attack_L2F   Attack_L3F (突进派生)
    │            │            │
    │ 摇杆后+攻   │ 摇杆后+攻   │
    ▼            ▼            ▼
  Attack_L1B   Attack_L2B   (上挑派生，L3 无后派生)

重攻击：
  Attack_Heavy（独立按键，可在任意轻攻击后取消进入）

空中攻击：
  二段跳后可发动 Attack_Air_1 → Attack_Air_2
  滑翔中可发动 Attack_Air_Glide（俯冲攻击）
```

### 2.3 连招窗口（Combo Window）

```
Attack_L1 → Attack_L2 窗口：
  开启：Attack_L1 的 60% 归一化时间 [AnimNotify]
  关闭：Attack_L1 的 95% 归一化时间 [AnimNotify]
  窗口内按攻击键 → 进入 Attack_L2
  窗口内不按攻击键 → 播放完 L1 后回 Idle

Attack_L2 → Attack_L3 窗口：同上逻辑
```

### 2.4 输入缓冲（Input Buffer）

```
缓冲窗口：[PLACEHOLDER: 0.3s]
作用：
  - 连招窗口开启前 0.3s 内按了攻击键 → 窗口开启时自动进入下一段
  - 缓冲去重：连续快速按攻击键不会导致一次按键触发两段连招
  - 缓冲队列深度 = 1（只保留最新一次输入）
```

**Rationale**：0.3s 是动作游戏的行业基准（鬼泣 5 也是 0.3s）。太短则"我已经按了为什么不连"的挫败感；太长则误触。

### 2.5 派生规则

| 当前段 | 摇杆方向 | 派生结果 | Rationale |
|--------|---------|---------|-----------|
| L1/L2 | 前推（>0.7） | 突进派生（L1F/L2F） | 追击敌人，向前位移 [PLACEHOLDER: 300cm] |
| L1/L2 | 后拉（>0.7） | 上挑派生（L1B/L2B） | 控场，将敌人挑飞 [PLACEHOLDER: 200cm 高] |
| L1/L2 | 不动（<0.3） | 标准连段（L2/L3） | 最高伤害 |
| L3   | 任意      | 无派生，回 Idle | L3 是终结段 |

### 2.6 Perfect Combo 系统

```
条件：在连招窗口的精确时机窗口内按下攻击键
精确窗口：[PLACEHOLDER: 连招窗口开启后 0.08s 内]
Perfect Combo 奖励：该段攻击伤害 × 1.3
视觉反馈：武器轨迹 + 闪光粒子
```

### 2.7 Attack03 飞剑终结段（当前实现）

第三段普攻保留角色位移与独立方向选择，同时把武器表现改为以下闭环：

```text
右手持剑
  → 可调延迟后脱手
  → 飞向角色前方目标（脱手瞬间锁定为世界坐标）
  → 在固定位置旋转
  → 飞向实时更新的左手 Socket
  → 重新挂回 Bip001LHand
```

- `URoverCombatComponent` 管理 `Waiting / Outbound / Spinning / Returning` 四个运行阶段；Montage 中断、闪避、受击、死亡和 watchdog 超时都会强制回收武器。
- `ARoverCharacter` 只提供武器脱挂、世界 Transform 更新和挂回接口，保持组件之间通过 Character 转发的架构约束。
- 武器 SkeletalMesh 始终关闭物理碰撞和物理模拟；实际命中继续使用 `WeaponTraceBase → WeaponTraceTip` 的多采样 Sphere Sweep，避免飞剑直接推动吊桥或其他物理物体。
- 飞出、旋转和飞回可分别开关判定；同一次 Attack03 继续使用 `HitActorsThisAttack` 去重，同一对象只受击一次。

手调入口：`Content/Rover/Combat/DA_RoverCombatConfig → Settings → Attack → Third Throw`。

| 分组 | 主要参数 | 作用 |
|------|----------|------|
| Timing | `StartDelay / OutboundDuration / SpinDuration / ReturnDuration` | 控制脱手时机和三阶段节奏 |
| Target | `TargetForwardOffset / TargetLateralOffset / TargetHeightOffset` | 相对角色位置和第三段攻击方向确定前方固定旋转点 |
| Rotation | `AnchorRotationOffset / SpinAxis / SpinDegreesPerSecond` | 调整剑到达后的朝向、旋转轴和速度 |
| Collision | 三阶段 Collision 开关、`TraceRadius / TraceSampleCount / TraceSubstepDistance / MaxTraceSubsteps` | 独立调整飞剑的判定范围、密度和高速移动防漏判 |

当前 `[PLACEHOLDER]` 默认节奏：`0.08s + 0.35s + 0.55s + 0.25s`；前方距离 `300cm`、高度 `80cm`；旋转速度 `1080°/s`；飞剑 Trace 半径 `18cm`。

## 3. 命中判定系统

### 3.1 判定架构

```
AnimNotify 驱动 Trace：
  AttackEnableHit → 开启每帧 Trace
  AttackDisableHit → 关闭 Trace

Trace 参数：
  类型：Sphere Trace（Multi）
  半径：[PLACEHOLDER: 20cm]（武器挥砍范围）
  起点：Weapon_Tip Socket（上一帧位置）
  终点：Weapon_Tip Socket（当前帧位置）
  通道：ECC_GameTraceChannel1（自定义 "Combat" 碰撞通道）

命中验证：
  HitID = AttackID + SegmentIndex + FrameIndex
  每个敌人每次攻击只命中一次（HashSet 去重）
```

### 3.2 攻击段数据

| 攻击段 | 判定开始 (归一化) | 判定结束 (归一化) | Trace 半径 | 基础伤害 |
|--------|-----------------|-----------------|-----------|---------|
| Attack_L1 | 0.15 | 0.35 | 20cm | 25 |
| Attack_L2 | 0.12 | 0.38 | 22cm | 30 |
| Attack_L3 | 0.10 | 0.45 | 25cm | 45 |
| Attack_L1F | 0.18 | 0.40 | 20cm | 22 |
| Attack_L2F | 0.15 | 0.42 | 22cm | 28 |
| Attack_Heavy | 0.25 | 0.55 | 30cm | 60 |

**Rationale**：
- L3 判定窗口最长 + 伤害最高 = 终结段的仪式感
- 突进派生（L1F/L2F）伤害略低于标准段 = 空间换伤害的 tradeoff

## 4. 受击系统

### 4.1 受击分级

| 受击类型 | 伤害阈值（单次） | 累积韧性阈值 | 动画 | 硬直时间 | 位移 |
|---------|---------------|------------|------|---------|------|
| Light Hit | 任意伤害 | — | Hit_Light_F/L/R/B | 0.25s | 后退 50cm |
| Heavy Hit | ≥ 50 | — | Hit_Heavy_F/B | 0.55s | 击退 200cm |
| Knockback | ≥ 80 | — | Hit_Knockback | 0.7s | 击退 400cm |
| Launch | — | 韧性归零 | Hit_Launch | 1.0s | 浮空 250cm |
| Air Hit | 浮空状态任意伤害 | — | Hit_Air | 0.3s | 空中受击位移 150cm |
| Down | 浮空后着地 | — | Hit_Down | 1.5s | — |
| Get Up | Down 后自动恢复 | — | Hit_GetUp | — | 起身回 Idle |

### 4.2 韧性系统（Poise / Stagger）

```
敌人韧性值：[PLACEHOLDER: 100]
每次被命中：韧性 -= 攻击的"削韧值"
韧性 > 0：根据单次伤害判断 Light/Heavy/Knockback
韧性 ≤ 0：进入 Launch 状态，韧性重置为 100

削韧值表：
  Attack_L1-L3: 15 / 20 / 35
  Attack_L1F-L2F: 18 / 25
  Attack_Heavy: 60
```

**Rationale**：韧性系统解决"无限连"问题——没有韧性的话，高攻速角色可以把敌人从头连到尾。韧性归零触发 Launch 是一个清晰的"你打穿了我的防御"信号。

### 4.3 受击方向判定

```
伤害来源方向 → 受击者朝向的夹角：
  0~45°   → Hit_Light_F（正面受击）或 Hit_Heavy_F
  45~135° → Hit_Light_L/R（侧面受击）
  135~180° → Hit_Light_B（背面受击）或 Hit_Heavy_B
```

## 5. 闪避系统

### 5.1 闪避参数

```
闪避距离：[PLACEHOLDER: 400cm]
闪避时长：[PLACEHOLDER: 0.35s]（含启动+位移+恢复）
无敌帧窗口：[PLACEHOLDER: 0.18s]（从闪避开始 0.05s 后开始的 0.18s）
                                          ↑ 留5帧给"我没躲掉"的反馈窗口
闪避方向：输入方向，无输入时 = 后方
闪避冷却：无（连续闪避允许，但每次闪避后 0.1s 内无敌帧不叠加）
```

### 5.2 闪避取消规则（核心手感）

```
可取消到闪避的状态和时机：

| 当前状态       | 可取消窗口                  | 不能取消              |
|---------------|---------------------------|---------------------|
| Attack_L1-L3  | 0% ~ 30% 归一化（前摇期）    | 30% 后（后摇+判定期）   |
| Attack_Heavy  | 0% ~ 15% 归一化            | 15% 后（蓄力不可打断） |
| MoveStop      | 0% ~ 40% 归一化            | 40% 后（制动不可打断） |
| Land_Heavy    | 不可取消                    | —                   |
| Land_Light    | 全程可取消（输入优先）         | —                   |
| Airborne      | 全程可取消                  | —                   |
```

**Rationale**：前摇可取消 = 攻击是一种"承诺"——你得决定这次挥刀是真打还是佯攻。一旦过了前摇窗口，你必须承受这次攻击的完整后果（打中或没打中都不能取消）。这是动作游戏"风险/回报"的基础。

### 5.3 完美闪避（Perfect Dodge）

```
触发条件：在敌人攻击判定帧前 [PLACEHOLDER: 0.15s] 内闪避
效果：
  - 时间减缓 0.3s（全局 Timescale 0.3）
  - 下 3s 内伤害 × 1.2
  - 视觉：蓝光粒子 + 音效 cue
```
